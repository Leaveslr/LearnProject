# 小红书技术笔记写作模式

## 选题原则

- 单点切入：一篇只解决一个核心问题。
- 面试导向：标题和正文要能回答一个真实追问。
- 收藏价值：提供对比表、流程图、回答模板、误区纠正。
- 不做空泛科普：每段都要增加理解、记忆或表达能力。

## 常用标题模型

- `别再把 X 理解成 Y 了`
- `大模型面试必问：X 到底是什么？`
- `一篇讲清楚 X 和 Y 的区别`
- `X 为什么能让大模型更快？`
- `X 的本质不是 A，而是 B`
- `面试官问 X，其实想听这 4 点`

## 技术正文结构

推荐结构：

1. 痛点：为什么这个知识容易混。
2. 一句话结论：先给可记住的主线。
3. 直觉类比：把抽象机制放到可想象场景。
4. 机制拆解：最多 3-4 个关键点。
5. 常见误区：指出错误理解。
6. 面试回答：给 30-60 秒可复述答案。

## Transformer/LLM 笔记常用表达

- “Attention 负责从上下文拿信息，FFN 负责加工当前 token。”
- “训练时能并行，是因为答案已知；推理时要逐 token，是因为未来还没生成。”
- “KV Cache 省的不是一次 Attention，而是历史 token 的 K/V 重复计算。”
- “RoPE 的关键不是加一个位置向量，而是让 Q/K 的点积天然带相对位置信息。”

## 配图卡片建议

- 卡 1：标题 + 一句话结论。
- 卡 2：机制流程图。
- 卡 3：对比表。
- 卡 4：常见误区。
- 卡 5：面试回答模板。

## 质量检查

- 标题是否具体，不是“大模型基础知识”这种泛标题？
- 开头是否说明“为什么值得看”？
- 正文是否有一个可复述的核心句？
- 是否有例子、对比或流程图建议？
- 是否有面试回答卡？
- 是否没有把复杂知识过度简化成错误结论？
