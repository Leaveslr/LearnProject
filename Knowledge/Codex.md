# Codex 整理说明

当我让 Codex 整理这个知识库时，请遵守这些规则。

## 基本原则

- 保持 Markdown 文件可读，避免依赖某个插件才能理解内容。
- 保留 Obsidian 双链格式，例如 `[[RAG]]`。
- 每篇笔记尽量只处理一个主题。
- 不要删除原始材料，除非我明确要求。
- 整理时优先把内容改写成我的话，而不是只摘抄。
- 当我提出新的整理建议、偏好、命名习惯或纠偏要求时，如果它适合长期复用，请把它补充进这份 `Codex.md`，让知识库规则可以持续迭代。
- 更新规则时保持简洁，优先追加可执行的原则或流程，不要把临时对话原文堆进规则文档。

## 推荐流程

1. 先读取 `Inbox/` 中的新内容。
2. 判断它属于 Note、Link、Project、Daily 还是 MOC。
3. 按 `Templates/` 中的格式整理。
4. 给出一句话总结、标签和相关链接。
5. 如果不确定分类，先保留在 `Inbox/` 并标记 `#todo`。
6. 如果原文已经是结构完整的综述、主题全景、技术路线图或资料汇总，优先把它作为 MOC 或参考型 MOC 保存，不要过度拆成零散笔记。
7. 单篇论文、文章精读、概念解释和方法论沉淀优先放到 `Notes/`；`Links/` 主要保存轻量链接、工具入口和待阅读资料。

## Daily 日志规则

- Daily 用来记录当天的流水、想法、问题、灵感和复盘线索，不要求完整、漂亮或系统。
- Daily 的重点是留下线索；真正值得长期保存的内容，后续再整理到 Notes、Links、Projects 或 MOCs。
- 每条记录尽量写清楚时间、背景和下一步，避免只写一个以后看不懂的短词。
- 如果某条 Daily 内容需要后续处理，请标记 `#todo`，并写明应该整理到哪个目录或主题。
- 整理 Daily 时不要把当天记录全部改写成长期笔记，只挑出反复出现、可复用、有行动价值的内容。
- Daily 文件建议使用日期命名，例如 `2026-04-29.md`。

## 论文与资料下载规则

- 下载的论文 PDF、官方 README 或网页快照放到 `Knowledge/Papers/`。
- 每篇论文或重要资料都应在 `Knowledge/Notes/` 中建立对应阅读笔记，不要只保存文件。
- 阅读笔记里需要写明原始链接、本地文件、核心问题、方法、关键结论和自己的理解。
- 如果资料不是正式论文，而是 GitHub 项目、官方博客或网页文章，请在笔记中标明资料类型，不要强行称为论文。

## 常用请求

- 帮我整理 `Inbox/` 里的新笔记。
- 帮我找出没有来源的笔记。
- 帮我把这些链接转成自己的知识笔记。
- 帮我生成某个主题的 MOC。
- 帮我找出重复或可以合并的笔记。

## 可直接复制的整理指令

```text
请作为我的知识库整理助手，读取当前 Markdown 知识库中的文档，并按照以下规则整理：

1. 先阅读 `Knowledge/Codex.md`、`Knowledge/Index.md` 和相关目录索引，理解当前知识库结构。
2. 优先处理 `Knowledge/Inbox/` 中的新内容，不要删除原始材料，除非我明确要求。
3. 判断每条内容适合归入哪一类：
   - 概念、方法、问题、观点：整理到 `Knowledge/Notes/`
   - 文章、工具、文档、网页链接：整理到 `Knowledge/Links/`
   - 具体目标、计划、任务、项目材料：整理到 `Knowledge/Projects/`
   - 每日流水、临时复盘：整理到 `Knowledge/Daily/`
   - 某个主题的总览和导航：整理到 `Knowledge/MOCs/`
4. 整理时优先使用 `Knowledge/Templates/` 中的模板格式。
5. 每篇笔记尽量只处理一个主题，标题要清楚、可搜索。
6. 把内容改写成我的话，不要只做摘抄。
7. 尽量补充这些信息：
   - 一句话总结
   - 关键要点
   - 来源
   - 标签
   - 相关笔记链接
8. 保留 Obsidian 双链格式，例如 `[[RAG]]`。
9. 如果发现重复主题，请提出合并建议，不要直接删除。
10. 如果不确定如何分类，先保留在 `Inbox/`，加上 `#todo`，并说明不确定的原因。
11. 整理完成后，请输出：
   - 新建或修改了哪些文件
   - 每个文件的主要变化
   - 还有哪些内容需要我确认
   - 下一步建议
12. 如果我在对话中提出新的整理偏好或规则，请判断它是否适合长期保留；适合的话，同步更新 `Knowledge/Codex.md`，并在结果中说明新增了什么规则。
13. 处理 Daily 日志时，只提炼其中有长期价值或行动价值的内容；普通流水保留在 Daily，不要过度整理。

请开始整理，并在修改前先简要说明你的整理计划。
```
