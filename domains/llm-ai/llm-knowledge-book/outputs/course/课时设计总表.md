# 课时设计总表

> 目标：把 10 周学习大纲拆成可直接执行的课程单元。每一讲都要有“目标、主线、例子、练习、验收”。

## 课时标准模板

每一讲使用同一结构：

```text
课程目标：本讲结束后学生能做什么。
核心问题：用一个问题牵引学习。
知识点：本讲覆盖哪些概念。
直觉例子：先用类比或最小例子建立理解。
机制拆解：讲清流程、公式或系统链路。
工程场景：说明它在哪里真实出现。
常见误区：指出最容易答错或用错的地方。
课堂练习：当场检查理解。
课后产出：沉淀成卡片、表格或项目片段。
验收标准：怎样算掌握。
```

## 每一阶段的最低通过线

| 阶段 | 最低通过线 |
| --- | --- |
| 基础阶段 | 能解释交叉熵、Embedding、Tokenizer、采样策略 |
| 架构阶段 | 能画 Transformer block，讲清 QKV、RoPE、GQA、MoE |
| 训练阶段 | 能区分预训练、SFT、LoRA、RLHF、DPO、GRPO |
| 推理阶段 | 能计算 KV Cache，解释 TTFT / TPOT / 量化 |
| 应用阶段 | 能设计 RAG 和 Agent，并说明评估与安全边界 |
| 面试阶段 | 能讲 1 个项目、1 个失败案例、10 个高频追问 |

## 课程讲解原则

- 每讲只解决一个核心问题。
- 先讲直觉，再讲公式和工程。
- 每讲至少有一个误区或反例。
- 每讲必须有课后产出。
- 不允许只讲定义，不讲场景和边界。
