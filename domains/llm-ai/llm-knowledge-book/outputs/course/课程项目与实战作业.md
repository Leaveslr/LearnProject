# 课程项目与实战作业

> 目标：让学习者不只会答概念题，还能把 LLM 知识落到真实系统、指标、排障和面试表达里。

## 作业分级

| 等级 | 目标 | 产出 |
| --- | --- | --- |
| 基础作业 | 检查单个知识点 | 面试卡、手算题、对比表 |
| 模块作业 | 检查一个模块的完整理解 | 系统图、排障表、评估集 |
| 综合项目 | 检查跨模块工程能力 | 项目方案、指标、失败案例、面试稿 |

## 项目 1：Tokenizer 与成本分析

### 任务

选择 5 条中文 prompt 和 5 条英文 prompt，分析 token 数差异，并说明它们对成本、上下文长度和 RAG chunk 的影响。

### 必须产出

- prompt 表格。
- token 数对比。
- 为什么 token 数不同的解释。
- 对 RAG chunk 和成本的影响。
- 一张 Tokenizer 面试卡。

### 验收标准

- 不只说“中文 token 多”，要能解释 tokenizer 粒度。
- 能把 token 数和 context length、费用、KV Cache 联系起来。

## 项目 2：Attention 可视化讲解

### 任务

用一个短句解释 Q/K/V 和 Attention 权重，不要求画复杂热力图，但必须讲清每个 token 如何选择参考对象。

### 必须产出

- 一个 4-6 token 的短句。
- Q/K/V 直觉解释。
- attention score 的最小表格。
- causal mask 解释。
- 一段 2 分钟讲解稿。

### 验收标准

- 能说清 Q 是“我在找什么”，K 是“我有什么特征”，V 是“我提供什么信息”。
- 能说明 scale 和 mask 的作用。

## 项目 3：KV Cache 显存估算与推理压测方案

### 任务

给定一个模型配置，估算不同 batch size 和上下文长度下的 KV Cache 显存，并设计压测指标表。

### 必须产出

- KV Cache 计算表。
- batch size / seq len 对显存影响分析。
- TTFT、TPOT、tokens/s、P95 延迟指标表。
- 优化建议：GQA、PagedAttention、Prefix Cache、量化。

### 验收标准

- 公式正确。
- 能解释显存和吞吐、延迟的取舍。
- 能说明为什么 KV Cache 是用显存换速度。

## 项目 4：RAG 企业知识库问答

### 任务

设计一个企业制度问答 RAG 系统，从文档入库到回答评估完整说明。

### 必须产出

- 系统架构图。
- 文档解析和 chunk 策略。
- embedding / BM25 / hybrid search 选择理由。
- rerank 设计。
- prompt 组织。
- 引用溯源方案。
- 10 条 golden set。
- 错误归因表。
- 权限控制方案。

### 验收标准

- 能解释 chunk size 为什么这么选。
- 能区分检索错误和生成错误。
- 能处理无答案和越权问题。
- 有明确指标，不只说“效果更好”。

## 项目 5：Agent 工具调用系统

### 任务

设计一个“调研分析 Agent”，它可以调用搜索、读取文档、总结、生成报告等工具。

### 必须产出

- workflow vs agent 选择理由。
- 工具列表。
- 每个工具的 schema。
- 状态管理设计。
- memory 设计。
- HITL 节点。
- trace 示例。
- eval 指标。
- 安全边界。

### 验收标准

- 工具 schema 参数清晰。
- 有错误恢复和最大步数限制。
- 高风险动作有人工确认。
- 评估不只看最终答案，也看 trace。

## 项目 6：LoRA 领域微调方案

### 任务

为一个客服风格改写或领域问答任务设计 LoRA 微调方案。

### 必须产出

- 为什么不用 prompt / RAG 的理由。
- 数据格式。
- loss mask 说明。
- LoRA target module。
- rank、learning rate、epoch 初始选择。
- 评估集。
- 过拟合和灾难性遗忘风险。
- 和 baseline 对比。

### 验收标准

- 能解释 LoRA 低秩假设。
- 能说明微调的目标是行为适配还是知识注入。
- 有离线和线上评估指标。

## 项目 7：安全红队与线上监控

### 任务

为一个 RAG + Agent 系统设计安全测试和线上监控方案。

### 必须产出

- prompt injection 测试用例。
- jailbreak 测试用例。
- 越权访问测试。
- 工具误调用测试。
- 数据泄露测试。
- 线上监控指标。
- 告警和人工接管策略。

### 验收标准

- 不只写安全概念，要能落到测试用例。
- 能区分输入风险、检索风险、工具风险和输出风险。

## 综合毕业项目

### 题目

设计一个“面向企业内部知识库的 RAG + Agent 助手”。

### 背景

企业有大量制度文档、项目文档和 FAQ，希望员工可以自然语言提问，并在需要时让 Agent 调用工具生成报告、检索资料或创建任务。

### 必须提交

1. 系统整体架构图。
2. 模型选择和部署方案。
3. RAG 设计。
4. Agent 设计。
5. 评估方案。
6. 安全方案。
7. 成本与延迟估算。
8. 失败案例和排障流程。
9. 30 秒项目介绍。
10. 2 分钟项目介绍。
11. 10 个面试追问回答。

### 评分 Rubric

| 维度 | 分值 | 标准 |
| --- | --- | --- |
| 原理正确性 | 20 | 对 LLM、RAG、Agent、推理的解释准确 |
| 工程完整性 | 20 | 系统链路完整，有真实约束 |
| 评估设计 | 15 | 有 golden set、指标和错误归因 |
| 安全设计 | 15 | 覆盖权限、注入、工具风险 |
| 成本与性能 | 10 | 能分析 TTFT、TPOT、并发和成本 |
| 面试表达 | 10 | 能讲 baseline、指标、失败案例 |
| 内容沉淀 | 10 | 有知识卡、面试卡或复盘文档 |

总分 85 分以上视为课程通过。
