# 知识卡：Agent 工具调用

## 资料来源

- 主笔记：[Agent 基础](../../src/06-Agent/01-Agent基础.md)

## 一句话结论

Agent 工具调用的本质，是让 LLM 在任务循环中选择合适工具、填对参数、读取结果并决定下一步，而不是只生成一段文本。

## 它解决什么问题

- 单次 LLM 调用只能回答，不会主动查数据、算结果或操作系统。
- 复杂任务需要多步计划、外部信息和环境反馈。
- 工具调用让模型从“说”扩展到“做”。

## 核心直觉

Agent 像一个会用工具的助理：

```text
看任务 -> 想下一步 -> 调工具 -> 看结果 -> 再决定 -> 最终回答
```

## 最小例子

任务：“查今天销售额并计算环比。”

- 选择数据库查询工具。
- 填入日期参数。
- 读取返回结果。
- 调用计算工具算环比。
- 生成解释和结论。

## 关键机制

- 工具注册：名称、描述、参数 schema、返回格式。
- 决策循环：plan / action / observation / answer。
- 错误恢复：参数错、工具失败、结果为空时重试或降级。
- 约束控制：权限、次数、成本、人工确认。

## 工程应用

- 数据查询、代码执行、文件处理、网页检索、业务系统操作。
- 需要 trace 记录每一步，便于评估和回放。
- 线上关注成功率、工具准确率、调用次数、延迟、越权风险。

## 常见误区

- 有 function calling 就等于 Agent。
- 工具越多越好。
- Agent 只要最终答案对，中间路径无所谓。

## 边界和反例

- 简单稳定流程更适合 workflow，不一定需要高自主 Agent。
- 高风险操作要 human-in-the-loop。
- 工具描述不清或 schema 太宽，会导致错误调用。
