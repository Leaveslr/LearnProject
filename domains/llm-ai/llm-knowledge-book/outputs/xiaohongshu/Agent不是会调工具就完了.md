## 推荐标题

Agent 不是会调工具就完了

## 封面文案

会调工具还不够

## 正文

很多人讲 Agent，只讲“LLM 可以调用工具”。

但真正难的是：怎么让它正确、可控、可评估地调用工具。

一句话结论：

> Agent 工具调用是一个带状态、约束和反馈的行动循环。

### 1. 工具调用循环

```text
理解任务 -> 选工具 -> 填参数 -> 执行 -> 看结果 -> 决定下一步
```

不是调用一次 API 就结束。

### 2. 工具 schema 很关键

好工具要有：

- 清楚的名称
- 明确的使用边界
- 强类型参数
- 稳定返回结构
- 可处理的错误码

### 3. 为什么要 trace？

只看最终答案不够。

Agent 可能中间走弯路、重复调用、参数填错，甚至越权操作。

trace 能复盘每一步。

### 4. 常见误区

误区：工具越多越强。  
正确：工具越多，误选工具的概率也会上升。

误区：有 function calling 就是 Agent。  
正确：Agent 还需要任务循环、状态管理和错误恢复。

## 面试回答卡

```text
Agent 工具调用不是单次 function calling，
而是在任务循环中选择工具、填写参数、执行、读取 observation，
再决定下一步。
工程上要关注工具 schema、权限控制、trace、错误恢复和人工确认。
```
