# 预训练数据工程

## 一句话结论

预训练数据决定基础模型的能力上限。模型不是简单“越大越好”，而是要吃到足够多、足够干净、配比合理、污染可控的数据。

## 1. 为什么数据工程重要

LLM 预训练看起来是在做 next token prediction，本质上是在从海量文本中压缩语言、知识、代码、推理模式和世界结构。

如果数据有问题，常见后果是：

- 垃圾文本太多，模型学会低质量表达。
- 重复数据太多，训练效率下降，容易记忆。
- 领域数据不足，专业能力差。
- benchmark 泄漏，评估分数虚高。
- 有害内容没处理，安全风险上升。

一句话：训练目标告诉模型怎么学，数据决定模型能学到什么。

## 2. 数据来源

常见预训练数据包括：

- 网页文本。
- 书籍。
- 论文。
- 代码。
- 问答社区。
- 百科和知识库。
- 多语言语料。
- 数学和推理数据。
- 合成数据。

不同数据来源带来的能力不同：

| 数据类型 | 主要贡献 |
| --- | --- |
| 网页 | 通用知识和语言覆盖 |
| 书籍 | 长文本结构和叙事能力 |
| 代码 | 编程、结构化推理、工具使用基础 |
| 论文 | 专业知识和严谨表达 |
| 数学 | 符号推理和分步解题 |
| 多语言 | 跨语言泛化 |

## 3. 数据清洗

清洗目标是去掉明显有害或低价值的内容。

常见步骤：

- HTML 解析。
- 去广告、导航、页脚。
- 语言识别。
- 低质量文本过滤。
- 敏感信息过滤。
- 有害内容过滤。
- 格式规范化。

清洗不是越狠越好。过滤太弱会污染训练，过滤太强会丢掉长尾知识和多样性。

## 4. 去重

去重分两类：

- 精确去重：完全相同内容。
- 近似去重：高度相似内容。

为什么重要：

- 重复数据会浪费训练 token。
- 模型可能记住重复样本。
- 评估集泄漏风险更高。
- 数据分布被热门重复内容扭曲。

常见方法包括 hash、MinHash、SimHash、embedding 相似度等。

## 5. 数据质量过滤

质量过滤可以用规则，也可以用模型。

规则例子：

- 文本长度过短过滤。
- 特殊字符比例过高过滤。
- 重复 n-gram 过多过滤。
- 乱码比例过高过滤。

模型过滤例子：

- 质量分类器。
- 安全分类器。
- 教育价值评分。
- 领域相关性评分。

## 6. 数据配比

数据配比会影响模型能力侧重。

例如：

- 代码数据提高编程能力，但比例过高可能影响普通语言风格。
- 数学数据提高推理能力，但要注意难度和格式。
- 中文数据不足会导致中文表达和知识弱。
- 高质量指令数据不适合直接混进普通预训练而不加区分。

数据配比不是固定公式，需要通过实验和评估调。

## 7. Benchmark Contamination

污染指训练数据里包含了测试集或高度相似内容。

后果：

- benchmark 分数虚高。
- 误判模型真实泛化能力。
- 面试或论文汇报时可信度下降。

常见处理：

- 对评估集做 hash 匹配。
- 做 n-gram 重叠检测。
- 做近似文本相似度检测。
- 对公开 benchmark 保持隔离。

## 8. 合成数据

合成数据可以补足稀缺能力，例如：

- 数学推理。
- 代码修复。
- 多轮问答。
- 工具调用。
- 安全拒答。

但合成数据也有风险：

- 模型味太重。
- 错误被放大。
- 多样性不足。
- 评估集污染。

合成数据通常需要筛选、验证和混合真实数据使用。

## 9. 面试追问

### Q1：预训练数据为什么要去重？

去重能减少训练浪费、降低记忆风险、避免重复样本扭曲分布，也能降低 benchmark 泄漏概率。

### Q2：数据配比怎么定？

先根据目标能力设定初始配比，再通过小规模实验、验证集指标和能力评测迭代调整。

### Q3：benchmark contamination 为什么严重？

因为它会让模型看过测试题，评估分数不能代表真实泛化能力，导致模型能力判断失真。

## 学习检查

学完本章后，应该能讲清：

- 数据清洗、去重、质量过滤、配比各自解决什么问题。
- 为什么预训练数据决定模型能力上限。
- 为什么 benchmark 泄漏会让评估失真。
