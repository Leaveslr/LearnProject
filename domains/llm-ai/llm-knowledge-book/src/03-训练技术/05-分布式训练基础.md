# 分布式训练基础

## 一句话结论

大模型训练放不进单卡，也跑不快，所以需要把数据、参数、计算和优化器状态分摊到多张卡、多台机器上。

## 1. 显存都被什么占了

训练时显存主要由这些部分组成：

- 模型参数。
- 梯度。
- 优化器状态。
- 激活值。
- 临时 buffer。

推理主要关心参数和 KV Cache；训练还要保存梯度、优化器状态和中间激活，因此显存压力更大。

## 2. Data Parallel

Data Parallel 把同一个模型复制到多张卡，每张卡处理不同数据。

流程：

```text
每张卡各算一份 batch
-> 反向传播得到梯度
-> 多卡同步梯度
-> 每张卡更新相同参数
```

优点：

- 概念简单。
- 适合模型能放进单卡的场景。

缺点：

- 每张卡都要完整保存模型、梯度和优化器状态。
- 模型太大时单卡仍然放不下。

## 3. Tensor Parallel

Tensor Parallel 把单层矩阵计算切到多张卡上。

例如一个很大的线性层：

```text
Y = XW
```

可以把 `W` 按列或按行切开，让不同 GPU 负责不同部分。

优点：

- 适合单层参数很大的模型。
- 推理和训练都常用。

缺点：

- 通信频繁。
- 对网络带宽要求高。

## 4. Pipeline Parallel

Pipeline Parallel 把模型不同层放到不同 GPU 上。

例如：

```text
GPU0: layer 1-10
GPU1: layer 11-20
GPU2: layer 21-30
```

优点：

- 可以把很深的模型拆开。

缺点：

- 有 pipeline bubble，部分设备会等待。
- 需要 micro-batch 提高利用率。

## 5. ZeRO

ZeRO 的核心思想是：不要让每张卡都保存完整训练状态。

常见阶段：

| 阶段 | 切分内容 |
| --- | --- |
| ZeRO-1 | 优化器状态 |
| ZeRO-2 | 优化器状态 + 梯度 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 |

ZeRO-3 能显著降低单卡显存压力，但通信和调度更复杂。

## 6. Activation Checkpointing

训练时激活值很占显存。Activation checkpointing 的做法是：

```text
前向时只保存部分激活
反向时重新计算未保存的激活
```

它用额外计算换显存。

## 7. Gradient Accumulation

如果单卡 batch 放不下，可以累积多个小 batch 的梯度，再更新一次。

```text
global batch size = micro batch size × accumulation steps × GPU 数
```

它能模拟更大的 batch，但会影响训练吞吐和优化动态。

## 8. 常见组合

真实大模型训练通常不是只用一种并行，而是组合：

```text
Data Parallel + Tensor Parallel + Pipeline Parallel + ZeRO + Activation Checkpointing
```

选择取决于：

- 模型大小。
- 序列长度。
- batch size。
- GPU 显存。
- GPU 间通信带宽。
- 训练框架。

## 9. 面试追问

### Q1：Data Parallel 和 Tensor Parallel 的区别？

Data Parallel 是多卡复制完整模型、切数据；Tensor Parallel 是把模型内部大矩阵计算切到多卡。

### Q2：ZeRO 解决什么问题？

ZeRO 通过切分优化器状态、梯度和参数，减少每张卡需要保存的训练状态，降低显存压力。

### Q3：Activation Checkpointing 的代价是什么？

它节省激活显存，但反向传播时需要重新计算一部分前向结果，因此增加计算时间。

- 为什么大模型训练通常要组合多种并行策略。
