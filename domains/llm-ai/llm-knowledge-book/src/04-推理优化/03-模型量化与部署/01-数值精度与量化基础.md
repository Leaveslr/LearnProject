## 3.1 数值精度格式详解

### 格式规格对比

| 格式 | 位数 | 结构 (符号/指数/尾数) | 范围(约) | 精度(约) | 主要用途 |
|:---|:---|:---|:---|:---|:---|
| **FP32** | 32 | 1 / 8 / 23 | $10^{\pm 38}$ | $10^{-7}$ | 训练基线 |
| **BF16** | 16 | 1 / 8 / 7 | $10^{\pm 38}$ | $10^{-2}$ | 训练（稳定范围） |
| **FP16** | 16 | 1 / 5 / 10 | $10^{\pm 5}$ | $10^{-3}$ | 推理加速 |
| **INT8** | 8 | 整数 + 缩放因子 | $[-128, 127] \times \text{scale}$ | 离散 | 训练后量化 |
| **INT4** | 4 | 整数 + 缩放因子 | $[-8, 7] \times \text{scale}$ | 离散 | 极致压缩 |
| **NF4** | 4 | 非均匀码本 | 归一化分布 | 优于INT4 | QLoRA量化 |

### 精度权衡分析

**核心权衡：范围 vs 精度**

- **BF16**：与 FP32 相同的 8 位指数，提供 $10^{\pm 38}$ 范围，但尾数缩减至 7 位。无需损失缩放即可保持训练稳定性。
- **FP16**：更高的 10 位尾数精度，但 5 位指数将范围限制在 $10^{\pm 5}$，无损失缩放时存在梯度溢出风险。
- **转换效率**：FP32↔BF16 仅需尾数截断/零填充；FP32↔FP16 在指数重映射时存在溢出风险。

### BF16 vs FP16：为什么训练用 BF16

```
FP16:
┌─────────────────────────────────────────┐
│ 符号(1bit) │ 指数(5bit) │ 尾数(10bit)  │
└─────────────────────────────────────────┘
问题：指数范围只有 ±16，无法表示较大的梯度值
风险：梯度爆炸时容易溢出（Inf/NaN）

BF16:
┌─────────────────────────────────────────┐
│ 符号(1bit) │ 指数(8bit) │ 尾数(7bit)  │
└─────────────────────────────────────────┘
优势：指数范围与 FP32 相同 (±128)，训练更稳定
```

## 3.2 量化技术深度解析

### 量化基础原理

量化通过将 FP16/FP32 权重映射到低比特整数表示来减小模型大小：

$$Q(w) = \text{round}(w/s) + z$$

推理时反量化：$w' = (Q(w) - z) \times s$

其中：
- $s$ 是缩放因子（scale）
- $z$ 是零点（zero point）
- $Q(w)$ 是量化后的整数

### PTQ vs QAT 对比

| 对比项 | PTQ（训练后量化） | QAT（量化感知训练） |
|--------|------------------|---------------------|
| **定义** | 训练完成后直接量化 | 训练时模拟量化过程 |
| **优点** | 简单快速，无需重新训练 | 精度保持更好 |
| **缺点** | 低比特精度损失大 | 训练成本高 |
| **适用场景** | 快速部署 | 极致精度要求 |

### 常用量化方法对比

| 方法 | 原理 | 位宽 | 类型 | 特点 | 适用场景 |
|------|------|------|------|------|----------|
| **GPTQ** | 基于Hessian矩阵的逐列量化 | 3-4 bit | PTQ | Weight-only量化，精度好 | GPU推理 |
| **AWQ** | 保护"重要"权重通道（按激活值判断） | 4 bit | PTQ | 无需反向传播，只需少量校准数据 | 4-bit下优于GPTQ |
| **GGUF** | llama.cpp专用格式 | 2-8bit | PTQ | Q2_K~Q8_0多种量化级别 | CPU推理（Ollama/llama.cpp） |
| **NF4** | 非均匀码本，针对LLM权重分布优化 | 4 bit | PTQ | 零附近更多量化级别 | QLoRA量化 |
| **QLoRA** | 4-bit基模型 + LoRA适配器 | 4 bit | QAT | 消费级GPU可微调65B模型 | 微调场景 |

### INT8 vs INT4 对比

| 特性 | INT8 | INT4 |
|:---|:---|:---|
| 映射范围 | $[-128, 127]$ | $[-8, 7]$ |
| 精度损失 | 通常<1%（正确校准） | 2-5% |
| 内存缩减 | 2× vs FP16 | 4× vs FP16 |
| 支持情况 | 主流推理引擎（TensorRT、ONNX Runtime） | 需更复杂量化（分组、逐通道） |

### NF4 非均匀量化原理

NF4（归一化浮点4）通过使用针对 LLM 权重分布优化的**非均匀 16 值码本**，解决 INT4 均匀量化的局限：

```python
# NF4 码本结构（近似）
nf4_codebook = [
    -1.0, -0.57, -0.35, -0.21, -0.12, -0.07, -0.03, 0,
     0.03,  0.07,  0.12,  0.21,  0.35,  0.57,  0.85, 1.0
]

# 关键洞察：LLM权重集中在零附近
# NF4 在零附近放置更多量化级别，保留关键精度
```

### 量化实战：GPTQ vs AWQ vs GGUF

```python
# GPTQ 量化（适合 GPU 推理）
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

quantize_config = BaseQuantizeConfig(
    bits=4,
    group_size=128,
    desc_act=True
)

model = AutoGPTQForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    quantize_config=quantize_config
)

# 校准数据量化
model.quantize(calibration_dataset)

# AWQ 量化（4-bit 效果更好）
from awq import AutoAWQForCausalLM

model = AutoAWQForCausalLM.from_pretrained("meta-llama/Llama-3-8B")
quant_config = {
    "zero_point": True,
    "q_group_size": 128,
    "w_bit": 4
}
model.quantize(tokenizer, quant_config=quant_config)

# GGUF 量化（适合 CPU/本地部署）
# 使用 llama.cpp 转换
# ./quantize models/llama-3-8b-f16.gguf models/llama-3-8b-q4_k_m.gguf q4_K_M
```

## 3.3 部署架构设计

### 部署挑战

| 挑战 | 说明 |
|:---|:---|
| **内存限制** | 70亿参数模型 FP16 格式需 ~14GB，超过消费级 GPU 显存 |
| **推理延迟** | 自回归生成受内存带宽限制，token 生成速度慢 |
| **规模化成本** | 服务数百万请求需要大规模计算基础设施 |

### 部署流程决策树

```
┌─────────────────────────────────────────────────────────┐
│                    部署目标设备分类                       │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  云GPU (A100/H100)                                       │
│  → 聚焦吞吐量 → INT8量化 + 大批量                       │
│                                                          │
│  边缘GPU (RTX 4090)                                       │
│  → 平衡延迟/吞吐量 → INT8/INT4混合 + 中等批量           │
│                                                          │
│  移动/嵌入式设备                                          │
│  → 最小化内存 → 蒸馏 + INT4/NF4                         │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 单机 vs 分布式部署架构

**单机部署架构**：
```
客户端 → API Gateway → vLLM/TRT-LLM → GPU
```

**分布式部署架构**：
```
客户端 → Load Balancer → [vLLM Instance 1 (TP=4)]
                        → [vLLM Instance 2 (TP=4)]
                        → [vLLM Instance 3 (TP=4)]
```

### 并行策略对比

| 方式 | 原理 | 通信模式 | 适用场景 |
|------|------|----------|----------|
| **张量并行 (TP)** | 单层切分到多卡 | AllReduce（频繁） | 多卡单机 |
| **流水线并行 (PP)** | 不同层在不同卡 | 点对点（较少） | 跨机部署 |
| **数据并行** | 副本在多卡，每个处理不同数据 | 梯度同步 | 训练/批量推理 |

```python
# vLLM 多卡部署示例
# 8 卡运行 72B 模型（张量并行）
python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-72B-Instruct \
    --tensor-parallel-size 8 \
    --gpu-memory-utilization 0.9

# TensorRT-LLM 多卡部署
trtllm-build --model_name /path/to/model \
    --tp_size 8 \
    --output_dir /path/to/engine
```

## 3.4 量化对推理的影响

### 推理优化性能对比

| 方法 | 内存 | 速度 | 精度 | 使用场景 |
|:---|:---|:---|:---|:---|
| FP16基线 | 14GB (7B) | 1.0× | 100% | 开发 |
| INT8 PTQ | 7GB | 1.5-2.0× | 99-99.5% | 标准服务 |
| INT4 PTQ | 3.5GB | 2.5-3.0× | 95-98% | 移动部署 |
| NF4 QLoRA | 3.5GB + 适配器 | 2.5-3.0× | 97-99% | 任务特定移动部署 |
| 混合INT4/INT8 | 5GB | 2.0-2.5× | 98-99% | 平衡部署 |

### 70亿模型量化后内存对比

| 方法 | 内存占用 |
|:---|:--- |
| **FP16 全量** | ~14GB (权重) |
| **INT8 PTQ** | ~7GB |
| **INT4 PTQ** | ~3.5GB |
| **QLoRA (4-bit)** | ~3.6GB (基座+适配器) |

### 量化实施注意事项

1. **校准数据**：PTQ 使用 512-1024 个覆盖领域分布的样本
2. **粒度选择**：逐通道量化通常比逐张量高 1-2% 精度
3. **对称 vs 非对称**：对称（零点=0）更快；非对称更好处理偏斜分布
4. **动态量化**：对不规则输入分布在运行时量化激活

## 3.5 知识蒸馏

### 蒸馏 vs 微调对比

| 方面 | 微调 | 蒸馏 |
|:---|:---|:---|
| **目标** | 适应新任务/领域 | 压缩模型大小 |
| **模型大小** | 不变 | 减小（2-10×） |
| **数据需求** | 标注任务数据 | 可使用无标注数据+教师模型 |
| **训练目标** | 任务特定性能 | 模仿教师行为 |
| **部署** | 相同基础设施 | 边缘设备、移动端 |
| **典型用途** | 领域专业化 | 延迟/成本降低 |

### 实用蒸馏策略

1. **预蒸馏微调**：先在领域数据上微调教师模型获取专业知识
2. **温度缩放**：使用 $T=2-5$ 软化教师预测：$p_i = \exp(z_i/T) / \sum_j \exp(z_j/T)$
3. **层匹配**：通过辅助损失将学生中间层与教师层对齐
4. **多教师集成**：从多个教师蒸馏以提升鲁棒性

```python
# 蒸馏损失函数示例
def distillation_loss(student_logits, teacher_logits, labels, temperature=2.0, alpha=0.5):
    # 软目标损失（KL散度）
    soft_loss = F.kl_div(
        F.log_softmax(student_logits / temperature),
        F.softmax(teacher_logits / temperature),
        reduction='batchmean'
    ) * (temperature ** 2)
    
    # 硬目标损失（交叉熵）
    hard_loss = F.cross_entropy(student_logits, labels)
    
    # 组合损失
    return alpha * soft_loss + (1 - alpha) * hard_loss
```

## 3.6 面试高频问题

### Q1: 量化后精度损失多少？

> **INT8**：通常 <1% 精度损失（正确校准）
> **INT4**：2-5% 精度损失
> **AWQ/GPTQ**：通过保护重要权重，4-bit 可控制在 2-3% 损失
> **关键**：校准数据质量直接影响量化效果

### Q2: GPTQ vs AWQ 区别？

> **GPTQ**：基于 Hessian 矩阵的逐列量化，3-4bit 精度好，但需要反向传播
> **AWQ**：按激活值判断重要权重通道，无需反向传播，只需少量校准数据
> **实际**：AWQ 在 4-bit 下通常优于 GPTQ，且更快

### Q3: BF16 vs FP16 区别？

> **FP16**：1/5/10 位结构，指数范围 ±16，有梯度溢出风险
> **BF16**：1/8/7 位结构，指数范围与 FP32 相同（±128），训练更稳定
> **建议**：训练用 BF16，推理可用 FP16 或 INT8

### Q4: 张量并行 vs 流水线并行怎么选？

> **张量并行 (TP)**：单层参数切分到多卡，通信频繁（AllReduce），适合多卡单机
> **流水线并行 (PP)**：不同层在不同卡，通信较少（点对点），适合跨机部署
> **实际**：70B+ 模型通常 TP=8，100B+ 可能需要 TP+PP 混合

### Q5: 量化部署流程是什么？

> 1. 选择量化方法（INT8/INT4/FP16）
> 2. 准备校准数据（512-1024 样本）
> 3. 执行量化（GPTQ/AWQ/GGUF）
> 4. 验证精度损失可接受
> 5. 部署到推理框架（vLLM/TensorRT-LLM）
