# RAG 评估与排障

## 一句话结论

RAG 出错时不能只怪模型。要把问题拆成检索、重排、上下文组织、生成、引用和评估数据六层逐步排查。

## 1. RAG 为什么难评估

RAG 是一个系统，不是单个模型调用。

一条回答可能经历：

```text
问题 -> query rewrite -> 检索 -> rerank -> prompt 拼接 -> 生成 -> 引用
```

任何一层出错，最终答案都会错。

## 2. 错误归因框架

建议按下面顺序排查：

| 层级 | 问题 |
| --- | --- |
| Query | 用户问题是否被正确理解 |
| Retrieval | 正确文档是否被召回 |
| Rerank | 正确文档是否排在前面 |
| Context | prompt 里是否放入了足够证据 |
| Generation | 模型是否忠实使用证据 |
| Citation | 引用是否对应真实来源 |

## 3. 检索评估

检索层要回答：正确证据有没有被找回来。

常见指标：

- Recall@K。
- Precision@K。
- MRR。
- nDCG。

RAG 早期最重要的是 Recall@K。如果正确材料没召回，生成模型通常无能为力。

## 4. 重排评估

rerank 要回答：正确证据是否排在足够靠前的位置。

如果 top-20 有正确文档，但 top-3 没有，可能需要：

- 更好的 reranker。
- query rewrite。
- 调整 chunk。
- 混合检索。

## 5. 答案评估

答案层常见维度：

- correctness：答案是否正确。
- faithfulness：是否忠实于上下文。
- relevance：是否回答了问题。
- completeness：是否完整。
- citation accuracy：引用是否准确。

注意：答案正确但引用错，在严肃业务里仍然是问题。

## 6. Golden Set

RAG 评估需要一组代表性问题，叫 golden set。

每条样本最好包含：

- 用户问题。
- 标准答案。
- 应命中文档。
- 关键证据片段。
- 难度标签。
- 场景标签。

不要只收简单问题。要覆盖：

- 高频问题。
- 长尾问题。
- 多跳问题。
- 易混淆问题。
- 无答案问题。
- 权限边界问题。

## 7. 常见故障与修复

| 现象 | 可能原因 | 修复方向 |
| --- | --- | --- |
| 答案胡编 | 没召回证据、prompt 约束弱 | 提升召回、加引用约束、无证据拒答 |
| 找到相似但不相关内容 | embedding 不适配、chunk 混杂 | 换 embedding、优化 chunk、加 rerank |
| 答案漏信息 | top-k 太小、chunk 切断 | 调整 top-k、chunk、上下文组织 |
| 引用不准 | 生成阶段没绑定来源 | 结构化引用、引用校验 |
| 多跳问题失败 | 单轮检索不够 | query decomposition、迭代检索、GraphRAG |
| 无答案也强答 | 缺少拒答策略 | 增加 no-answer 样本和阈值 |

## 8. RAG 和微调怎么选

优先 RAG：

- 知识经常更新。
- 需要引用来源。
- 私有文档很多。
- 希望可追溯。

优先微调：

- 要改变输出风格。
- 要学习固定格式。
- 要适配领域任务模式。
- 知识相对稳定。

很多系统会组合：RAG 提供知识，微调改善行为。

## 9. 面试追问

### Q1：RAG 答错了怎么排查？

先看正确证据有没有被召回，再看 rerank 排名、prompt 中是否包含证据、模型是否忠实使用证据，最后看引用和评估样本是否合理。

### Q2：如何构造 RAG golden set？

从真实用户问题、业务高频问题、失败案例和专家标注中抽样，每条样本包含标准答案和应命中的证据文档。

### Q3：如何判断是检索问题还是生成问题？

如果正确证据没进入上下文，是检索或重排问题；如果正确证据在上下文里但回答仍错，是生成、prompt 或模型能力问题。

## 学习检查

学完本章后，应该能讲清：

- RAG 错误如何分层归因。
- Recall@K、faithfulness、citation accuracy 分别评估什么。
- 如何设计一个可用的 RAG golden set。
