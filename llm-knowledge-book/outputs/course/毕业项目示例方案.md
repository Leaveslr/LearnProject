# 毕业项目示例方案

> 题目：企业内部知识库 RAG + Agent 助手。

## 1. 项目背景

企业内部有制度文档、项目文档、FAQ 和流程说明。员工经常需要查询政策、生成报告、整理资料或创建任务。原流程依赖人工搜索和询问同事，效率低、引用不清、答案容易过期。

## 2. 项目目标

构建一个内部助手：

- 能回答制度和文档问题。
- 回答时提供引用来源。
- 无答案时拒答或建议人工咨询。
- 对复杂调研任务可以调用工具生成报告。
- 对高风险动作加入人工确认。
- 支持评估、监控和安全审计。

## 3. 总体架构

```text
用户问题
-> 权限检查
-> query rewrite / intent routing
-> RAG 检索链路
   -> 文档解析
   -> chunk
   -> embedding / BM25
   -> hybrid search
   -> rerank
   -> context assembly
-> LLM generation
-> citation check
-> 如果需要执行任务，进入 Agent workflow
   -> plan
   -> tool call
   -> observation
   -> HITL
   -> final answer
-> logging / trace / eval
```

## 4. 模型选择

基础方案：

- 生成模型：选择通用指令模型，优先稳定性和成本。
- embedding 模型：选择中文和领域术语表现好的模型。
- reranker：选择 cross-encoder 或 bge-reranker 类模型。

选型原则：

- 问答准确率优先于生成风格。
- embedding 需要用内部 golden set 测召回。
- 生成模型要看忠实性和拒答能力。
- 部署时同时看 TTFT、TPOT、吞吐和成本。

## 5. RAG 设计

### 文档入库

处理流程：

```text
文档收集 -> 权限元数据 -> 解析 -> 清洗 -> 分块 -> embedding -> 建索引
```

chunk 策略：

- 制度文档按标题层级优先。
- FAQ 按问答对切分。
- 长文档保留章节路径。
- chunk 元数据包含文档版本、部门、权限、更新时间。

### 检索

使用 hybrid search：

- BM25 处理关键词和制度编号。
- 向量检索处理语义相似。
- RRF 融合结果。
- rerank 进行精排。

### 生成

prompt 要求：

- 只基于给定证据回答。
- 给出引用。
- 证据不足时拒答。
- 多版本冲突时优先最新版本。

## 6. Agent 设计

只有复杂任务进入 Agent，不把所有问答都做成 Agent。

Agent 适用任务：

- 多文档调研。
- 总结多个制度差异。
- 生成报告。
- 创建待办或工单草稿。

工具示例：

```text
search_docs(query, filters)
read_doc(doc_id)
summarize_chunks(chunks)
create_report(outline, evidence_ids)
create_task_draft(title, assignee, evidence)
```

HITL 节点：

- 创建任务前人工确认。
- 发送报告前人工确认。
- 涉及敏感部门文档时人工确认。

## 7. 评估方案

Golden set 字段：

| 字段 | 说明 |
| --- | --- |
| question | 用户问题 |
| expected_answer | 标准答案 |
| evidence_doc_ids | 应命中文档 |
| key_spans | 关键证据片段 |
| difficulty | 简单 / 多跳 / 易混淆 |
| permission_level | 权限要求 |
| no_answer | 是否无答案 |

指标：

- Recall@5。
- rerank nDCG。
- answer correctness。
- faithfulness。
- citation accuracy。
- no-answer accuracy。
- tool success rate。
- Agent task success rate。

## 8. 安全方案

风险与控制：

| 风险 | 控制 |
| --- | --- |
| 越权访问 | 检索前 ACL 过滤 |
| prompt injection | 外部文档按不可信输入处理 |
| 数据泄露 | 敏感字段脱敏，输出前检测 |
| 工具误调用 | 工具分级、参数校验、HITL |
| 幻觉 | 引用约束、无证据拒答 |
| 过期文档 | 版本字段和时效性 rerank |

## 9. 成本与性能

关注指标：

- TTFT。
- TPOT。
- input tokens。
- output tokens。
- cache hit rate。
- GPU memory。
- 每请求成本。

优化方向：

- 固定 system prompt 用 prefix cache。
- 长文档检索前过滤。
- top-k 和 rerank 数量控制。
- 高频问答缓存。
- 小模型处理简单路由，大模型处理复杂生成。

## 10. 失败案例

案例：引用旧版本制度。

现象：

用户问报销标准，系统引用了旧制度。

排查：

- 生成答案看似正确。
- 检查 trace 后发现旧制度被检索并排在前面。
- 根因是 chunk 元数据没有版本字段，rerank 只看语义相关性。

修复：

- 增加文档版本和生效日期。
- 检索阶段过滤过期文档。
- rerank 加入时效性特征。

指标：

旧文档误引用率从 18% 降到 3%。

## 11. 30 秒项目介绍

我做的是一个企业内部知识库 RAG + Agent 助手，目标是让员工能直接查询制度、生成调研报告，并且答案带引用、可追溯。系统采用文档解析、混合检索、rerank、引用校验和 Agent 工具调用。我的重点是 RAG 评估、错误归因和 Agent 安全边界，最终把 top-5 召回率和引用准确率显著提升，同时通过权限过滤和 HITL 控制风险。

## 12. 2 分钟项目介绍

这个项目的背景是企业内部文档多、版本复杂，员工查制度和整理资料效率低。我们设计了一个 RAG + Agent 助手，简单问答走 RAG，复杂调研进入 Agent。

RAG 部分先对文档做解析、清洗和按章节分块，入库时保留权限、版本、更新时间等元数据。检索采用 BM25 + 向量检索的混合方案，再用 reranker 精排，最后让模型基于证据生成并输出引用。

Agent 部分只处理多步骤任务，比如生成调研报告。它有搜索、读取文档、总结、生成报告草稿等工具，高风险动作通过 human-in-the-loop 确认。

评估上我们构造 golden set，覆盖高频问题、多跳问题、无答案问题和权限边界问题。指标包括 Recall@5、faithfulness、citation accuracy 和 tool success rate。一个典型失败案例是旧版本制度误引用，后来通过版本字段和时效性 rerank 修复。
