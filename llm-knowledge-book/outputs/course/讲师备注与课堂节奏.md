# 讲师备注与课堂节奏

> 目标：把课程从“能读”升级成“能讲”。每节课都要有开场问题、节奏控制、容易卡住的点和收束方式。

## 通用课堂节奏

每讲 45-60 分钟：

```text
0-5 分钟：提出反直觉问题
5-15 分钟：建立直觉例子
15-30 分钟：机制拆解
30-40 分钟：工程场景和误区
40-50 分钟：练习与追问
50-60 分钟：总结和课后产出
```

## L04 Tokenizer

开场问题：

```text
为什么“我爱大模型”和“I love LLM”在模型眼里不是同样长度？
```

容易卡住：

- 学员容易把 token 等同于词。
- 学员容易忽略 tokenizer 对成本和上下文长度的影响。

讲解建议：

- 先用中文、英文、代码三种文本对比。
- 再讲 BPE 从字符合并。
- 最后落到 token budget、RAG chunk 和费用。

收束：

```text
Tokenizer 是模型看世界的颗粒度，不只是预处理工具。
```

## L07 Attention / QKV

开场问题：

```text
一句话里的每个词，怎么知道当前该参考谁？
```

容易卡住：

- Q/K/V 三者抽象。
- 学员会把 attention 权重当成最终信息。

讲解建议：

- 用“查资料”类比 Q/K/V。
- 用 4-token 短句做最小例子。
- 强调 QK 算权重，V 被加权聚合。

收束：

```text
Attention 的核心不是记住所有词，而是动态决定当前 token 该看谁。
```

## L10 MHA / MQA / GQA / MLA

开场问题：

```text
为什么模型效果还没变，推理显存却能省很多？
```

容易卡住：

- 学员容易以为减少的是 query heads。
- MLA 容易讲得过抽象。

讲解建议：

- 先从 KV Cache 显存公式进入。
- 再解释 KV heads 数量。
- MLA 只讲“压缩 KV 表示”直觉，不强行展开全部细节。

收束：

```text
这些注意力变体的核心动机之一，是让推理更便宜。
```

## L17 LoRA / QLoRA

开场问题：

```text
为什么不改完整模型，也能让模型适配新任务？
```

容易卡住：

- 低秩假设。
- A/B 矩阵形状。
- target module 选择。

讲解建议：

- 用“给原模型加修正器”的类比。
- 画出 `W + BA`。
- 用参数量计算说明省在哪里。

收束：

```text
LoRA 不是把模型重训一遍，而是学习一个小的任务增量。
```

## L19 KV Cache

开场问题：

```text
为什么模型生成越长，显存压力越大？
```

容易卡住：

- 学员以为 KV Cache 省显存。
- 学员分不清 prefill 和 decode。

讲解建议：

- 先讲无 cache 时重复计算历史 token。
- 再讲 cache 存 K/V。
- 最后做显存公式练习。

收束：

```text
KV Cache 是用显存换 decode 速度。
```

## L25 RAG 评估排障

开场问题：

```text
RAG 答错了，到底该怪检索还是模型？
```

容易卡住：

- 学员会直接调 prompt。
- 忽略 citation accuracy。

讲解建议：

- 用一条错误回答做分层排查。
- 强调先看证据有没有召回。
- 再看生成是否忠实。

收束：

```text
RAG 是系统问题，必须分层归因。
```

## L27 Agent 工具调用

开场问题：

```text
模型会调用工具，就等于 Agent 做好了吗？
```

容易卡住：

- 学员把 function calling 等同 Agent。
- 忽略工具 schema 和错误恢复。

讲解建议：

- 先区分 workflow 和 agent。
- 展示一个坏 schema 和好 schema。
- 用 trace 展示失败定位。

收束：

```text
Agent 工程的关键是可控，不是炫技。
```

## L31 安全红队

开场问题：

```text
如果检索到的文档里写着“忽略所有规则”，模型该听谁？
```

容易卡住：

- 学员只想到用户输入攻击。
- 忽略 RAG 文档和工具风险。

讲解建议：

- 区分 prompt injection 和 jailbreak。
- 强调外部文档是不可信输入。
- 把安全落到权限、工具、日志和监控。

收束：

```text
LLM 安全不是一句拒答规则，而是全链路控制。
```

## L32 项目表达

开场问题：

```text
为什么“我做了一个 RAG 项目”听起来没有技术深度？
```

容易卡住：

- 学员只堆技术名词。
- 没有 baseline、指标、失败案例。

讲解建议：

- 用背景、问题、方案、指标、失败案例模板。
- 要求每个人写 30 秒版本。
- 再追问一个失败案例。

收束：

```text
项目表达的核心是证明你做过真实取舍。
```
