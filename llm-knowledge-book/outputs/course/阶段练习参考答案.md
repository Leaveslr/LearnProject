# 阶段练习参考答案

> 说明：本文件不是标准背诵答案，而是判断回答是否达标的参考框架。真正掌握的标准是能换例子、能讲边界、能回答追问。

## 阶段一：基础原理与 Tokenizer

### 交叉熵和最大似然是什么关系？

参考答案：

最大似然是让模型给真实样本更高概率。语言模型每一步希望正确 token 的概率越高越好。把最大化概率写成最小化目标时，会变成最小化负对数概率，也就是交叉熵。

达标要点：

- 说出“最大化真实 token 概率”。
- 说出 `-log P(correct token)`。
- 能说明概率越低惩罚越大。

### BPE 为什么能处理未登录词？

参考答案：

BPE 从字符或 byte 级别开始，逐步合并高频片段。遇到没见过的新词时，可以把它拆成已经存在的 subword 或字符片段，因此不会像 word-level tokenizer 那样直接 OOV。

达标要点：

- 说出 subword。
- 说出从小颗粒合并。
- 能举新词拆分例子。

### temperature、top-k、top-p 分别控制什么？

参考答案：

temperature 调整概率分布的尖锐程度；top-k 固定保留概率最高的 k 个候选；top-p 保留累计概率达到 p 的候选集合。temperature 影响随机性，top-k/top-p 限制采样范围。

达标要点：

- temperature 不是过滤，而是重塑分布。
- top-k 是固定数量。
- top-p 是动态数量。

## 阶段二：Transformer 与现代架构

### Q、K、V 分别是什么？

参考答案：

Q 可以理解为当前 token 在问“我需要找什么信息”；K 是每个 token 提供的可匹配特征；V 是真正被聚合的信息内容。Attention 先用 Q 和 K 算相关性，再用相关性加权 V。

达标要点：

- QK 算权重。
- 权重加权 V。
- 不把 K 和 V 混成一回事。

### 为什么 Attention 要除以 `sqrt(d_k)`？

参考答案：

当向量维度变大时，Q 和 K 的点积方差会变大，softmax 容易变得过于尖锐，导致梯度不稳定。除以 `sqrt(d_k)` 可以让分数尺度更稳定。

达标要点：

- 说出维度变大导致点积尺度变大。
- 说出 softmax 饱和或过尖。
- 说出稳定训练。

### GQA 为什么能降低 KV Cache？

参考答案：

GQA 让多组 query heads 共享较少的 key/value heads。KV Cache 存的是每层每个 token 的 K 和 V，所以 KV heads 变少，缓存显存和读取带宽都会下降。

达标要点：

- 说出减少的是 K/V 头数。
- 能和 KV Cache 公式联系。
- 不说成减少 query heads。

## 阶段三：训练、微调与对齐

### 预训练、SFT、RLHF、DPO 分别解决什么？

参考答案：

预训练让模型学习语言和世界知识的统计结构；SFT 让模型学会按指令回答；RLHF 通过人类偏好训练 reward model，再用强化学习优化策略；DPO 直接用偏好对优化模型，不单独训练显式 reward model。

达标要点：

- 预训练：能力底座。
- SFT：指令格式和行为。
- RLHF：偏好奖励。
- DPO：直接偏好优化。

### LoRA 的低秩假设是什么？

参考答案：

LoRA 假设下游任务对模型权重的改变量可以用低秩矩阵近似。它冻结原始权重，只训练两个小矩阵 A 和 B，让 `ΔW = BA`，从而用少量参数适配任务。

达标要点：

- 原权重冻结。
- 训练低秩增量。
- 说出参数高效。

### DP、TP、PP、ZeRO 分别切什么？

参考答案：

DP 切数据，每张卡一份完整模型；TP 切单层张量计算；PP 切模型层；ZeRO 切优化器状态、梯度和参数，降低每张卡保存的训练状态。

达标要点：

- DP 切 batch。
- TP 切矩阵。
- PP 切层。
- ZeRO 切训练状态。

## 阶段四：推理优化与部署

### KV Cache 显存怎么算？

参考答案：

近似公式：

```text
batch_size × seq_len × num_layers × 2 × num_kv_heads × head_dim × bytes_per_element
```

其中 `2` 代表 K 和 V 两份。显存随 batch size、序列长度、层数、KV 头数线性增长。

达标要点：

- 公式正确。
- 知道 `2` 是 K/V。
- 知道 GQA/MQA 为什么能降显存。

### TTFT 和 TPOT 有什么区别？

参考答案：

TTFT 是从请求开始到第一个 token 返回的时间，主要受 prefill、排队、prompt 长度影响。TPOT 是生成阶段每个输出 token 的耗时，主要受 decode、KV Cache、显存带宽和 batch 调度影响。

达标要点：

- TTFT 对应首 token。
- TPOT 对应后续 token。
- 能联系 prefill / decode。

## 阶段五：RAG 系统

### RAG 答错了如何排查？

参考答案：

先看 query 是否被正确理解，再看正确证据是否召回；如果召回了，看 rerank 是否排到前面；再看上下文是否包含证据；如果证据在上下文中但答案仍错，就是生成或 prompt 问题；最后检查引用是否准确。

达标要点：

- 分层排查。
- 先检索后生成。
- 能说出 citation 也要评估。

### RAG 和微调怎么选？

参考答案：

知识频繁更新、需要引用、私有文档多时优先 RAG；需要改变输出风格、固定格式、领域行为模式时考虑微调。很多系统会组合使用。

达标要点：

- RAG 补知识。
- 微调改行为。
- 能说组合策略。

## 阶段六：Agent 系统

### workflow 和 agent 的边界是什么？

参考答案：

workflow 是人预先写好流程，模型只在节点里做判断或生成；agent 是模型在约束内动态决定下一步行动。流程明确、稳定性要求高时优先 workflow；路径开放、需要动态工具选择时才用 agent。

达标要点：

- workflow 更可控。
- agent 更灵活但成本和风险更高。
- 不把 tool calling 直接等同 agent。

### 为什么 Agent eval 必须看 trace？

参考答案：

Agent 的最终答案可能对，但过程可能调用了错误工具、越权访问或浪费成本；最终答案也可能错，需要通过 trace 定位是规划、工具、记忆、状态还是生成问题。因此 Agent eval 要看执行轨迹。

达标要点：

- 过程可观测。
- 错误归因。
- 成本和安全也要评估。

## 阶段七：评估、安全与面试

### prompt injection 和 jailbreak 有什么区别？

参考答案：

prompt injection 更强调用户输入或外部文档试图覆盖系统指令，RAG 文档里也可能藏攻击；jailbreak 更强调诱导模型绕过安全策略，输出本不该输出的内容。

达标要点：

- injection 是指令干扰。
- jailbreak 是绕过安全。
- RAG 文档也可能注入。

### 项目为什么必须讲 baseline 和失败案例？

参考答案：

baseline 说明你的方案到底提升了什么，没有 baseline 就无法证明改进；失败案例说明你真的经历过问题定位和工程取舍，不只是调用 API。面试官通过这些判断真实深度。

达标要点：

- baseline 量化提升。
- 失败案例体现经验。
- 能讲排查过程。
