# 面试卡：Agent 工具调用

## 高频问法

- Agent 和普通 LLM 调用区别？
- Function calling 就是 Agent 吗？
- 工具调用失败怎么恢复？

## 30 秒回答

Agent 工具调用是让 LLM 在任务循环中选择工具、填写参数、执行、观察结果并决定下一步。它不只是 function calling，而是带状态、约束、反馈和错误恢复的行动循环。工程上要设计清楚工具 schema、权限、trace、重试和人工确认。

## 2 分钟回答

简单 LLM 调用通常是一次输入一次输出。Agent 面向目标任务，会在感知、推理、行动、观察之间循环。工具调用的核心包括工具注册表、参数 schema、执行器、状态/trace 和 guardrail。一个好工具要边界清晰、参数少而明确、返回结构稳定。失败时需要根据错误类型处理：参数错就修正重试，结果为空就换查询策略，高风险操作就请求人工确认。评估时不能只看最终答案，还要看工具选择、参数正确率、调用次数、成本、延迟和越权风险。

## 追问

### Q1：workflow 和 agent 区别？

回答：workflow 路径固定、可控；agent 路径更动态，适合不确定多步任务，但风险和评估成本更高。

### Q2：工具 schema 怎么设计？

回答：名称明确、描述包含使用边界、参数强类型、必填字段少、返回结构稳定，并写清错误码。

### Q3：为什么要保存 trace？

回答：trace 能复盘中间决策，定位工具误用、循环、越权和成本问题。

## 容易翻车

- 错误：工具越多越好。
- 正确：工具越多越需要清晰边界，否则会增加误调用。
