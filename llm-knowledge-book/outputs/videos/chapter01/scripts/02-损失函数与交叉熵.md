# 02-损失函数与交叉熵 视频讲解脚本

标题：损失函数与交叉熵

| 段落 | 时长 | 字幕/旁白 | 画面类型 |
| --- | ---: | --- | --- |
| 1 | 6.5s | 模型训练时，必须有一个扣分规则。损失函数就是告诉模型：你这次猜得有多离谱。 | title |
| 2 | 8.0s | 比如上下文是“我今天很”，真实答案是“开心”。模型给“开心”的概率越高，扣分越少。 | bars |
| 3 | 8.0s | 最大似然的直觉是：让训练数据里真实出现的 token，在模型眼里越来越可信。 | pipeline |
| 4 | 8.0s | 对单个样本，交叉熵可以先记成：Loss 等于负的 log 正确 token 概率。 | formula |
| 5 | 8.0s | 为什么取 log？因为多个 token 的概率相乘会变得很小，取 log 后可以变成相加，更稳定。 | compare |
| 6 | 8.0s | 语言模型每一步其实是在超大词表里做分类：lm_head 输出 logits，softmax 变成 token 概率。 | pipeline |
| 7 | 8.0s | Perplexity 是交叉熵的指数形式，可以理解为模型对下一个 token 的平均困惑程度。 | compare |
| 8 | 8.0s | 但 loss 或 PPL 低，不等于对话质量一定好。指令遵循、事实性和工具调用还要单独评估。 | trace |
| 9 | 8.0s | 做指令微调时，常见做法是只让 assistant 的回答承担 loss，用户问题更多是条件，不是要模型模仿的答案。 | trace |
| 10 | 8.0s | 记住三句话：loss 是扣分规则；交叉熵惩罚不相信正确 token；评估 LLM 不能只看 loss。 | summary |
