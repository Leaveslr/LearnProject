# 概念例子例题讲懂交叉熵

结构：概念 -> 例子 -> 例题 -> 总结

## 01. title / 6.8s
这条视频只讲清一件事：交叉熵到底是什么。先讲概念，再用一个例子把它讲明白。

## 02. compare / 7.4s
先讲概念：交叉熵不是模型结构，而是训练时的评分规则。它决定模型这一步该被扣多少分。

## 03. compare / 7.4s
它解决的问题是：正确答案已经给出来了，模型却给了很多候选概率。我们要把这次预测变成一个分数。

## 04. tokens / 7.2s
语言模型每一步不是只吐一个词，而是给词表里所有候选 token 分配概率。正确 token 的概率最关键。

## 05. pipeline / 7.2s
这些概率来自 logits。模型先打原始分数，再用 softmax 把分数归一成概率。

## 06. formula / 7.4s
公式只需要记住这个版本：Loss 等于负的 log 正确 token 概率。正确概率越高，扣分越低。

## 07. tokens / 7.2s
现在跑例子：前文是“我今天很”，真实下一个 token 是“开心”。

## 08. bars / 7.4s
训练前，模型给“开心”的概率只有 0.30，还把不少概率分给了“难过”和“北京”。

## 09. trace / 7.4s
把 0.30 代进公式，loss 大约是 1.20。意思是：模型有点相信，但还不够相信。

## 10. trace / 7.4s
反向传播后，训练会推动“开心”的 logit 上升，同时把抢概率的错误候选压下去。

## 11. bars / 7.4s
训练后，如果“开心”的概率升到 0.72，loss 就会明显下降。

## 12. compare / 7.4s
这里还有两个细节：一个 batch 会平均很多 token 的 loss；指令微调还会用 mask 决定哪些 token 参与扣分。

## 13. tokens / 7.4s
接下来做例题：前文换成“天气非常”，正确 token 是“好”。模型一开始给“好”的概率是 0.20。

## 14. compare / 7.4s
请先判断：如果训练后 P(好) 从 0.20 升到 0.60，loss 会上升还是下降？

## 15. trace / 7.4s
答案是下降。因为交叉熵只看正确 token 的概率；0.60 比 0.20 更相信正确答案。

## 16. trace / 7.4s
带数字看更稳：P 等于 0.20 时 loss 约 1.61；P 等于 0.60 时 loss 约 0.51。

## 17. trace / 7.4s
再加一问：如果 SFT 里把用户问题也算进 loss，模型可能会学着复述用户，而不是只学习回答。

## 18. trace / 7.4s
所以你现在应该能判断三件事：P 正确提高，loss 降；mask 决定目标；PPL 低不代表任务一定成功。

## 19. trace / 8.0s
最后总结：概念上，交叉熵是扣分规则；例子里，它推高正确 token；例题里，你要能判断 loss 为什么变。
