# 评估与迭代记录

## 最终结构

概念：交叉熵是训练时的扣分规则，不是模型结构。
例子：用“我今天很 -> 开心”展示正确 token 概率从 0.30 到 0.72 时，loss 为什么下降。
例题：换成“天气非常 -> 好”，让观众判断 P(好) 从 0.20 到 0.60 时 loss 怎么变，并给出数值解释。
总结：沉淀三个判断规则：正确概率越高 loss 越低；mask 决定训练目标；PPL 低不等于任务一定成功。

## 本轮流程迭代沉淀

### 1. 剧本生成流程

原流程只强调“概念 -> 例子 -> 例题”，但实际生成时发现：如果概念段没有先讲清“它是什么”，用户会把后面的公式当成孤立规则。因此流程已迭代为：

```text
概念 -> 例子 -> 例题 -> 总结
```

概念段新增四个必答问题：

1. 它是什么？
2. 它解决什么问题？
3. 它看什么输入，给什么输出？
4. 它在系统里扮演什么角色？

本视频对应答案：

- 交叉熵不是模型结构，而是训练时的扣分规则。
- 它解决“正确答案已知，但模型给了一堆概率，如何把预测变成分数”的问题。
- 它看正确 token 的概率，输出一个 loss。
- 它负责告诉训练过程“这一步错得有多严重”。

### 2. 例子和例题的分工

例子负责把机制带着用户走一遍；例题负责让用户自己走一遍。例题必须和例子同构但不完全相同。

本视频中：

- 例子：`我今天很 -> 开心`，看 P(开心) 从 0.30 到 0.72，loss 下降。
- 例题：`天气非常 -> 好`，看 P(好) 从 0.20 到 0.60，判断 loss 是否下降。

这能检查用户是否真的理解 `Loss = -log P(正确 token)`，而不是只记住“开心”这个例子。

### 3. 视频生成流程

本轮发现两个画面问题并已修复：

- `trace` 视图中短文本被强行拉宽，导致字号异常放大。修复方式：把 `right.set(width=7.6)` 改成 `right.set(max_width=7.6)`。
- `summary` 视图在长句动画进入时出现重叠。流程修正：长总结优先使用 `trace` 三行规则，不使用编号长句硬塞。

新增抽帧要求：

1. 概念入口帧
2. 贯穿例子关键帧
3. 例题提问和答案帧
4. 总结稳定帧
5. 总结动画进入早期帧

只看最终稳定帧不够，因为文字重叠可能只发生在动画进入阶段。

### 4. 新的通过标准

下一条视频必须通过四个用户视角问题：

```text
它是什么？
细节怎么发生？
这个例子为什么这样跑？
换一个相似题，我能不能判断？
```

如果其中任意一项答不上来，优先迭代剧本；如果剧本已通过但画面阻碍理解，再迭代 Manim 模板。
