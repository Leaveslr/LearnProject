# 用一个例子讲懂交叉熵 视频讲解脚本

贯穿例子：`我今天很 -> 开心`

| 段落 | 时长 | 字幕/旁白 | 画面类型 |
| --- | ---: | --- | --- |
| 1 | 6.5s | 这次只用一个例子讲懂交叉熵：上下文是“我今天很”，真实下一个 token 是“开心”。 | title |
| 2 | 7.5s | 训练时，模型不是直接写答案，而是给整个词表里的每个候选 token 分配概率。 | tokens |
| 3 | 7.5s | 如果模型现在只给“开心”百分之三十的概率，它不是完全错，但还不够相信正确答案。 | bars |
| 4 | 7.5s | 这些概率来自 logits。logits 是模型给每个 token 的原始分数，softmax 把分数变成概率。 | pipeline |
| 5 | 7.5s | 可以把 logits 先理解成候选答案的打分：开心分高，难过也有分，但最后要归一成概率。 | trace |
| 6 | 7.5s | softmax 做的事是：分数越高，概率越大；但所有候选 token 的概率加起来必须等于一。 | formula |
| 7 | 7.5s | 交叉熵只盯一个数：真实 token“开心”的概率。概率越低，loss 越大。 | formula |
| 8 | 7.5s | 带入数字就很清楚：P 等于 0.9 时 loss 约 0.11；P 等于 0.3 时约 1.2；P 等于 0.01 时约 4.6。 | trace |
| 9 | 7.5s | 为什么取负 log？因为它会狠狠惩罚“把正确答案看得很低”的情况，这正是训练最想修的错。 | compare |
| 10 | 7.5s | 一句话有很多 token，整句概率本来要连续相乘；取 log 后，就能把乘法变成每一步 loss 相加。 | pipeline |
| 11 | 7.5s | 所以最大似然和最小交叉熵其实在做同一件事：让真实训练文本在模型眼里更可能出现。 | compare |
| 12 | 7.5s | loss 反向传播后，会推动“开心”的分数上升，同时压低那些抢概率的错误候选。 | trace |
| 13 | 7.5s | 训练几轮后，如果“开心”的概率从百分之三十升到七十二，交叉熵就会明显变小。 | bars |
| 14 | 7.5s | 在一个 batch 里，模型会对很多位置都算 loss，最后通常取平均，得到这一步训练的总扣分。 | pipeline |
| 15 | 7.5s | 做指令微调时，还要用 loss mask。用户问题是条件，通常不让模型因为没复述用户问题而扣分。 | trace |
| 16 | 7.5s | Perplexity 可以理解为平均困惑度。它来自交叉熵，但只能说明语言建模是否顺，不等于任务一定成功。 | compare |
| 17 | 7.5s | 现在你能判断了：正确 token 概率变高，loss 会下降；mask 错了，模型会学错目标。 | trace |
| 18 | 8.0s | 三句话总结：logits 先变概率；交叉熵惩罚不相信正确 token；训练就是不断把正确答案的概率推高。 | summary |
