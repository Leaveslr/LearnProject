# 用一个例子讲懂交叉熵：评估与迭代记录

## 目标

只用一个贯穿例子 `我今天很 -> 开心`，让用户真正理解交叉熵：

- 知道它是怎么回事：惩罚模型不相信正确 token。
- 知道细节是什么：logits、softmax、概率、`-log P(正确 token)`、batch 平均、loss mask。
- 能判断为什么这么做：正确 token 概率越高 loss 越低；mask 决定训练目标；PPL 低不等于任务成功。

## V1 评估

评分：88/100

优点：

- 贯穿例子明确，用户能知道 loss 在扣什么分。
- 覆盖 logits、softmax、交叉熵、最大似然、反向传播、PPL、SFT mask。
- 结尾有判断题，方向正确。

主要问题：

- `softmax` 仍然偏公式化，用户可能知道“分数变概率”，但未必知道分数表是什么。
- `Loss = -log P(开心)` 讲了方向，但数值直觉不够硬，用户不一定能判断 P 从 0.3 到 0.01 的惩罚差距。

## V2 迭代

新增两段：

1. logits 作为候选答案打分表：开心分高，难过也有分，softmax 把所有分数放到一起比较。
2. 交叉熵数值直觉：`P=0.90 -> loss≈0.11`，`P=0.30 -> loss≈1.20`，`P=0.01 -> loss≈4.60`。

抽帧检查：

- `00:00:25`：logits 到 softmax 链路清楚。
- `00:00:36`：原始分数表可读，能理解候选答案都有分。
- `00:00:48`：loss 公式和概率高低关系清楚。
- `00:01:25`：反向传播后“正确 logit 推高、错误概率压低”的训练动作明确。
- `00:02:02`：结尾判断题完整。

## 最终评估

评分：96/100

通过标准：

- 用户能复述：交叉熵不是看模型最终输出对不对，而是看正确 token 的概率够不够高。
- 用户能解释：softmax 先把 logits 归一成概率，交叉熵再对正确 token 的概率取负 log。
- 用户能判断：如果 `P(正确 token)` 从 0.3 提高到 0.7，loss 会下降。
- 用户能判断：如果 SFT 的 loss mask 错了，模型会学习错误目标。
- 用户能判断：PPL 低只能说明语言建模困惑度低，不保证事实性、指令遵循或工具调用成功。
