# 学习笔记到内容创作工作流

这个知识库同时服务两个目标：

1. 作为自己的 LLM 基础知识学习笔记。
2. 作为小红书图文笔记和短视频脚本的基础数据。

核心原则：先把知识学明白，再做内容表达。不要直接把原始资料改写成内容。

## 三层资料结构

```text
raw  ->  src  ->  content output
原始资料  学习笔记   小红书/视频
```

### 1. raw：资料来源

用途：

- 保存外部项目、论文、图片、代码和原始面试题。
- 追溯知识来源。
- 遇到不确定概念时回查。

不建议：

- 直接拿 raw 生成小红书笔记。
- 把 raw 中的问答原样放进正文。

### 2. src：个人学习笔记

用途：

- 建立自己的知识体系。
- 把概念、公式、工程场景和面试追问整理清楚。
- 形成可长期复习的主线笔记。

每篇学习笔记建议包含：

- 这个知识点解决什么问题。
- 核心概念和直觉解释。
- 必要公式或流程图。
- 工程应用场景。
- 常见误区。
- 面试追问。
- 可转化成内容的角度。

模板见：[学习笔记模板](../../templates/学习笔记模板.md)。

### 3. content output：对外内容

用途：

- 把学习笔记转换成小红书图文。
- 把复杂知识点拆成短视频脚本。
- 把面试题转成系列内容。

模板：

- [小红书图文笔记模板](../../templates/小红书图文笔记模板.md)
- [短视频脚本模板](../../templates/短视频脚本模板.md)

## 内容转化流程

### Step 1：选题

从一个具体知识点开始，不要一次讲完整章节。

好的选题：

- KV Cache 到底缓存了什么？
- RoPE 为什么能表示相对位置？
- LoRA 为什么只训练两个小矩阵？
- RAG 为什么不是接个向量库就完事？
- DPO 为什么不需要显式奖励模型？

不好的选题：

- 一篇讲完大模型。
- Transformer 全解析。
- RAG 从入门到精通。

### Step 2：提炼一句话结论

每个内容先写一句核心结论：

```text
KV Cache 的本质不是加速一次 Attention，而是避免自回归生成时重复计算历史 token 的 K/V。
```

这句话决定小红书标题和视频开头。

### Step 3：拆成 3-5 个解释点

建议结构：

1. 它解决什么问题。
2. 直觉上怎么理解。
3. 关键公式或流程。
4. 工程里有什么坑。
5. 面试怎么回答。

### Step 4：选择内容形态

| 内容形态 | 适合主题 | 输出重点 |
| --- | --- | --- |
| 小红书图文 | 概念对比、面试高频、学习路线 | 标题、封面、分点、收藏价值 |
| 短视频 | 原理解释、误区纠正、流程推演 | 开头钩子、口播节奏、画面提示 |
| 长文笔记 | 系统知识、公式推导、工程方案 | 完整性、准确性、可复习 |

### Step 5：反向校验

发布前检查：

- 是否有一句清楚的核心结论？
- 是否避免了“术语堆术语”？
- 是否有例子或类比？
- 是否说明了适用边界？
- 是否能回答一个面试追问？

## 选题库维护方式

建议每学完一个章节，在文末补一个“内容选题”小节：

```markdown
## 内容选题

- 小红书：KV Cache 为什么能让大模型推理变快？
- 视频：用 60 秒讲清楚 KV Cache 缓存了什么
- 面试：KV Cache 的显存占用怎么估算？
```

后续可以把这些选题集中整理成内容排期。

```text
知识卡 -> 讲解稿 -> 面试卡 -> 小红书图文 -> 短视频脚本 -> Rubric 自评
```

## 推荐系列

### 系列一：LLM 面试高频

- Transformer 为什么不用 BatchNorm？
- RoPE、ALiBi、绝对位置编码有什么区别？
- MHA、MQA、GQA、MLA 怎么选？
- LoRA 和全量微调到底差在哪？
- DPO 和 RLHF 的核心区别是什么？

### 系列二：LLM 工程落地

- KV Cache 为什么吃显存？
- vLLM 的 PagedAttention 解决了什么？
- INT8、INT4、NF4 量化怎么选？
- RAG 召回不准怎么排查？
- Agent 为什么容易失控？

### 系列三：从零建立知识体系

- 大模型学习路线怎么排？
- 算法岗需要掌握哪些 LLM 基础？
- 学 RAG 前必须懂哪些检索知识？
- 学 Agent 前必须懂哪些工程概念？
- 面试项目应该怎么复盘？
