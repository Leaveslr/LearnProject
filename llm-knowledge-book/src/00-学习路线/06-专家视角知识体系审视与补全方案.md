# 专家视角知识体系审视与补全方案

> 目标：把当前 `llm-knowledge-book` 从“可学习的资料体系”继续推进成“完整、通俗、可复习、可面试、可输出内容的 LLM 知识体系”。

## 一句话结论

当前体系的主干方向是对的：已经覆盖了基础、Tokenizer、Transformer、训练对齐、推理部署、RAG、Agent、多模态、评估和面试。

但如果目标是“整体掌握 LLM”，还需要从专家视角补三件事：

1. 把基础概念拆得更细，让初学者知道每个公式和工程选择到底解决什么问题。
2. 把训练、推理、RAG、Agent 串成一条真实工程链路，而不是各学各的。
3. 给每个知识点固定一套讲解模板：直觉、机制、公式、工程场景、常见坑、面试追问。

## 当前体系判断

### 已经做得比较好的地方

| 模块 | 评价 |
| --- | --- |
| 学习路线 | 已经有 30 天和 10 周路径，适合启动学习 |
| Transformer 主线 | Attention、位置编码、GQA/MLA、MoE 已经能支撑核心理解 |
| 训练与对齐 | 已覆盖预训练、SFT、RLHF、DPO、GRPO、LoRA、PEFT |
| 推理优化 | 已覆盖 KV Cache、FlashAttention、PagedAttention、量化、vLLM |
| RAG / Agent | 已经有系统架构、工程实践和面试题 |
| 面试闭环 | 真实题库素材较多，后续可以映射回知识点 |

### 目前最大的问题

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 基础层太压缩 | 初学者容易知道名词但说不清为什么 | 拆出损失函数、优化器、归一化、Embedding、采样策略专题 |
| 部分章节像“资料摘录” | 阅读时会跳，不像连续课程 | 每章统一成“直觉 -> 原理 -> 工程 -> 面试”的结构 |
| 评估和安全偏薄 | 做项目时容易只讲方案，不会讲指标和风险 | 增加 LLM eval、RAG eval、Agent eval、安全与线上监控专题 |
| 现代工程链路不够完整 | 不足以完整解释一个真实 LLM 产品如何上线 | 增加数据工程、服务架构、成本估算、观测、回归测试 |
| 面试题没有完全映射知识点 | 复习效率低，题库和主线割裂 | 建立“知识点 -> 高频题 -> 标准回答 -> 追问”的索引 |

## 最终知识体系应该长什么样

建议最终形成 12 个一级模块。每个模块都要既能学习，也能复习和面试。

### 0. 学习方法与知识地图

要解决的问题：怎么学、先学什么、每个阶段学到什么程度算过关。

应包含：

- 总体知识地图。
- 30 天轻量路线。
- 10 周系统路线。
- 学习状态表。
- 知识点输出模板。
- 面试复盘模板。

掌握标准：

- 能说清 LLM 学习的主线不是“背 Transformer”，而是“模型如何表示语言、如何训练、如何推理、如何接入应用、如何评估上线”。

### 1. 数学与机器学习基础

要解决的问题：为什么 LLM 里的 loss、优化器、向量、归一化总是反复出现。

应包含：

- 概率、条件概率、最大似然。
- 交叉熵、KL 散度、perplexity。
- 梯度下降、AdamW、学习率调度、warmup。
- Embedding、向量相似度、矩阵乘法。
- 残差连接、LayerNorm、RMSNorm。
- 激活函数、SwiGLU。

通俗讲法：

- 交叉熵：模型对正确答案越没信心，惩罚越大。
- Embedding：把离散词变成可计算的位置，让语义相近的东西在空间里更接近。
- 优化器：不是直接“教会模型”，而是一步步调整参数，让错误变小。

### 2. Tokenizer 与语言模型基础

要解决的问题：文本为什么要先切成 token，为什么预测下一个 token 可以产生智能表现。

应包含：

- word、character、subword。
- BPE、WordPiece、SentencePiece。
- 中文、代码、多语言 token 问题。
- special tokens、chat template。
- next token prediction。
- decoding：greedy、beam search、temperature、top-k、top-p。
- context length、token budget、压缩表达。

通俗讲法：

- Tokenizer 是模型的“输入颗粒度”。颗粒切得太粗，没法处理新词；切得太细，序列变长、成本变高。
- Next token prediction 表面是在猜下一个词，本质是在学习上下文里各种模式的统计规律。

### 3. Transformer 与现代模型架构

要解决的问题：现代 LLM 为什么大多长成 Decoder-only Transformer，内部每一层到底做什么。

应包含：

- Transformer block。
- Self-Attention、Causal Mask、Cross-Attention。
- Q/K/V 的直觉和矩阵计算。
- FFN、SwiGLU。
- Residual、Pre-Norm、Post-Norm、RMSNorm。
- RoPE、ALiBi、长上下文外推。
- MHA、MQA、GQA、MLA。
- MoE、router、专家负载均衡。
- Dense vs MoE。
- Llama、Qwen、DeepSeek、Gemma、Mistral 等架构差异。

通俗讲法：

- Attention 像是在一句话里给每个词找“当前最该参考谁”。
- FFN 像是每个 token 自己做一次更复杂的特征加工。
- GQA/MQA 的核心不是让模型更聪明，而是让推理时 KV Cache 更省。

### 4. 预训练与数据工程

要解决的问题：一个基础模型是怎么从海量文本里学出来的。

应包含：

- 自监督学习。
- 预训练目标函数。
- 数据来源、清洗、去重、质量过滤。
- 数据配比、多语言配比、代码数据。
- contamination 与 benchmark 泄漏。
- scaling laws。
- 训练稳定性。
- checkpoint、断点恢复、实验管理。
- 分布式训练：data parallel、tensor parallel、pipeline parallel、ZeRO。

通俗讲法：

- 预训练不是给模型灌知识点，而是让它在海量文本中学会“语言和世界知识的统计结构”。
- 数据质量会影响模型上限，训练技巧更多是在保证模型稳定地吃下这些数据。

### 5. 指令微调与对齐

要解决的问题：基础模型为什么还不能直接当聊天助手，怎样让它更听指令、更符合偏好。

应包含：

- SFT。
- instruction data。
- chat template。
- loss masking。
- reward model。
- RLHF / PPO。
- DPO / IPO / KTO。
- GRPO / DAPO / GSPO。
- RFT。
- alignment tax。
- safety alignment。

通俗讲法：

- 预训练让模型“会说话”，SFT 让模型“按要求说话”，偏好对齐让模型“更像人希望的方式说话”。
- DPO 的直觉是：直接让模型更偏向好答案、更远离差答案，不单独训练奖励模型。

### 6. 微调与领域适配

要解决的问题：当通用模型不适合具体业务时，如何低成本适配。

应包含：

- 全参数微调。
- LoRA、QLoRA、AdaLoRA。
- Prefix Tuning、Prompt Tuning、Adapter。
- 数据构造、数据混合、增量训练。
- 灾难性遗忘。
- 训练评估。
- 模型合并、权重管理。
- 什么时候用微调，什么时候用 RAG。

通俗讲法：

- LoRA 像是在原模型旁边加一个小的“修正器”，不重写整本书，只在关键地方写批注。
- 微调适合改变模型行为习惯，RAG 适合补充外部知识。

### 7. 推理优化与部署

要解决的问题：模型训练好了，怎么低成本、低延迟、高吞吐地服务用户。

应包含：

- prefill / decode。
- KV Cache 显存计算。
- FlashAttention。
- PagedAttention。
- Continuous Batching。
- Prefix Cache。
- Speculative Decoding。
- Quantization：FP16、BF16、FP8、INT8、INT4、NF4。
- GPTQ、AWQ、GGUF。
- vLLM、SGLang、TensorRT-LLM、llama.cpp。
- 服务指标：TTFT、TPOT、QPS、吞吐、显存、成本。
- 多卡部署与并行策略。

通俗讲法：

- 训练像一次性读完整本书做练习，推理像一个字一个字往外写，所以推理瓶颈经常在显存带宽和 KV Cache。
- PagedAttention 像给 KV Cache 做分页内存管理，避免长短请求混在一起时浪费显存。

### 8. RAG 与知识增强

要解决的问题：模型不知道最新知识或私有知识时，如何让它查资料后回答。

应包含：

- 文档解析、清洗。
- chunk 策略。
- embedding 模型。
- 向量数据库。
- BM25、向量检索、混合检索。
- rerank。
- query rewrite。
- multi-hop retrieval。
- GraphRAG。
- citation 与溯源。
- RAG eval。
- RAG 排障：检索错、上下文错、生成错、引用错。

通俗讲法：

- RAG 不是“把资料塞进 prompt”，而是一个“先找证据，再组织答案”的系统。
- 检索召回决定有没有把正确材料拿回来，生成忠实性决定有没有按材料回答。

### 9. Agent 与工具使用

要解决的问题：什么时候需要让模型不只是回答，而是规划、调用工具、执行任务。

应包含：

- workflow vs agent。
- function calling / tool use。
- ReAct。
- Plan-and-Execute。
- state 与 memory。
- short-term / long-term memory。
- HITL。
- 多 Agent 协作。
- MCP。
- guardrails。
- observability：trace、latency、token cost、success rate。
- agent eval。
- 失败恢复：工具失败、循环、幻觉调用、权限越界。

通俗讲法：

- Workflow 是人提前写好流程，模型只填关键步骤；Agent 是模型在约束内动态决定下一步。
- Agent 的难点不是“会不会调用工具”，而是“调用错了怎么办、何时停止、如何验证结果”。

### 10. 多模态大模型

要解决的问题：图像、语音、视频如何接入语言模型。

应包含：

- CLIP、ViT、视觉编码器。
- projector / adapter / Q-Former。
- image token。
- LLaVA、Qwen-VL、InternVL 等架构。
- 多模态 SFT。
- OCR、图表理解、视觉问答。
- 视频多模态。
- 多模态评估。
- 多模态幻觉。

通俗讲法：

- 多模态模型通常不是让 LLM 直接“看图”，而是先把图变成一串 LLM 能读的视觉 token。

### 11. 评估、安全与上线监控

要解决的问题：如何知道系统真的变好了，如何发现线上风险。

应包含：

- LLM eval。
- RAG eval。
- Agent eval。
- LLM-as-judge。
- golden set。
- 人工标注与一致性。
- A/B test。
- hallucination。
- prompt injection。
- jailbreak。
- 数据泄露。
- 内容安全。
- 线上监控、回归测试、报警。

通俗讲法：

- 评估不是最后打分，而是整个开发过程的方向盘。
- 平均分不能代表可靠性，真实系统还要看坏案例、长尾问题和失败原因。

### 12. 面试、项目表达与内容输出

要解决的问题：把学到的知识转成面试可讲、项目可讲、内容可输出。

应包含：

- 高频面试题索引。
- 知识点到题目的映射。
- 项目 STAR 表达。
- baseline、指标、ablation、失败案例。
- 简历项目追问清单。
- 小红书图文模板。
- 短视频脚本模板。
- 复习卡片。

通俗讲法：

- 面试不是背标准答案，而是能把问题放回“原理、工程约束、取舍、失败案例”这条线上回答。

## 每个知识点的统一讲解标准

为了保证“细节能通俗易懂地讲明白”，建议所有核心章节都使用同一套结构。

```text
1. 一句话结论：先让读者知道这个概念解决什么问题。
2. 生活类比：用一个不失真的类比建立直觉。
3. 机制拆解：分步骤讲它怎么工作。
4. 必要公式：只保留真正影响理解的公式，并解释每个符号。
5. 工程场景：它在训练、推理、RAG、Agent 或部署中哪里出现。
6. 常见坑：初学者容易误解什么，工程中哪里会翻车。
7. 面试追问：准备 3 个从浅到深的问题。
8. 输出练习：学习笔记、面试卡、内容选题至少选一个。
```

示例：讲 KV Cache 时不要只说“缓存 K/V 能加速”，而要讲：

- 自回归生成为什么每次只新增一个 token。
- 没有 cache 时为什么旧 token 会被重复计算。
- cache 省的是计算，不是完全省显存。
- 长上下文和 batch size 为什么会让 cache 爆显存。
- MQA/GQA 为什么能减少 K/V 头数。
- 面试追问如何计算 KV Cache 显存。

## 推荐补齐优先级

### P0：先补“学习连续性”

这些是学习时最容易卡住的点，应该优先独立成章：

1. 损失函数与交叉熵。
2. Embedding 与向量相似度。
3. 优化器、AdamW 与学习率调度。
4. 归一化、残差连接与激活函数。
5. 解码与采样策略。
6. Transformer 知识点依赖图。
7. KV Cache 显存计算专题。

### P1：再补“工程完整性”

这些决定能不能讲清真实项目：

1. 预训练数据工程。
2. 分布式训练与显存优化。
3. 推理服务指标与压测。
4. RAG 评估与排障。
5. Agent 工程化设计。
6. LLM / RAG / Agent 线上监控。

### P2：最后补“面试与内容闭环”

这些决定复习效率和对外输出：

1. 知识点到面试题映射表。
2. 每章 3 个高频追问。
3. 项目表达模板。
4. Tokenizer 完整样例：学习笔记 + 面试卡 + 小红书图文 + 视频脚本。
5. Attention 完整样例。

## 学习顺序建议

如果目标是系统掌握，建议按下面顺序学：

1. 基础原理：交叉熵、Embedding、优化器、归一化。
2. Tokenizer：BPE、中文 token、next token prediction、采样。
3. Transformer：Attention、Mask、FFN、Norm、RoPE。
4. 现代架构：GQA、MLA、MoE、主流模型对比。
5. 训练链路：预训练、SFT、RLHF、DPO、GRPO。
6. 微调适配：LoRA、QLoRA、数据构造、评估。
7. 推理部署：KV Cache、量化、vLLM、并发与成本。
8. RAG：chunk、embedding、rerank、评估与排障。
9. Agent：workflow、tool、memory、trace、eval。
10. 多模态：视觉编码器、投影层、视觉 token、VLM 训练。
11. 评估安全：golden set、LLM-as-judge、线上监控、安全风险。
12. 面试与项目：把所有知识点映射到项目表达和追问。

## 是否已经足够开始学习

可以开始学，而且建议现在就开始。

但学习时要注意：当前版本适合作为“第一轮主线教材”，不是最终完备版。最好的推进方式是边学边补：

- 学到一个核心点，补一个“通俗解释”。
- 遇到一个面试题，挂回对应知识点。
- 做完一个模块，产出一张复习卡。
- 每周选择一个知识点做成内容样例。

这样它会从资料库自然长成真正属于你的 LLM 知识体系。
