# 知识讲解生产体系

> 目标：把一个技术知识点从“资料”稳定转化为“学得懂、讲得清、能面试、能发布”的内容资产。

## 一、体系定位

当前项目已经有两类沉淀：

- `llm-knowledge-book/src`：知识主题、学习笔记、面试材料和内容选题。
- `teaching-algorithm-methods`：复杂知识讲解方法、脚本模板、质量检查和验证案例。

新的生产体系负责把两者接起来：

```text
原始资料 -> 知识卡 -> 讲解稿 -> 面试卡 -> 内容稿 -> 反馈迭代
```

核心原则：

- 先确认知识点解决什么问题，再解释定义。
- 先建立直觉和例子，再进入公式、流程或代码。
- 每个知识点都必须有适用边界、常见误区和反例。
- 面试表达和内容表达都不能脱离原始知识卡。
- 每次输出后都要用质量 Rubric 自评，低于标准就继续迭代。

## 二、四层结构

### 1. 知识资产层

用途：把一个知识点整理成可复习、可追问、可转化的基本单元。

标准产物：

- 学习笔记：放在 `llm-knowledge-book/src/**`。
- 知识卡：放在 `llm-knowledge-book/outputs/knowledge-system/`。

知识卡必须回答：

- 它解决什么问题？
- 不用它时会怎样？
- 核心直觉是什么？
- 最小例子是什么？
- 关键机制是什么？
- 工程里怎么用？
- 它什么时候不能用？
- 面试官会怎么追问？
- 可以转成哪些内容选题？

### 2. 讲解方法层

用途：把知识卡转成学习者能跟上的认知路径。

默认使用 `teaching-algorithm-methods` 的主链路：

```text
问题场景 -> 已有经验 -> 直觉模型 -> 手算/可视化 -> 最小形式化 -> 实现/机制 -> 正确性/复杂度/成本 -> 易错点/反例 -> 迁移练习
```

技术知识不一定都有代码。如果没有代码，就把“代码实现”替换成：

- 系统流程。
- 张量形状变化。
- 请求生命周期。
- 工程配置。
- 伪代码或计算过程。

### 3. 内容产品层

用途：把同一个知识点转成不同使用场景的成品。

每个核心知识点至少产出四类内容：

| 产物 | 目标 | 默认位置 |
| --- | --- | --- |
| 讲解稿 | 讲清楚机制和边界 | `teaching-algorithm-methods/validation-cases/` |
| 面试卡 | 形成可回答的表达 | `llm-knowledge-book/outputs/interview-cards/` |
| 小红书图文 | 面向收藏和传播 | `llm-knowledge-book/outputs/xiaohongshu/` |
| 短视频脚本 | 面向口播和演示 | `llm-knowledge-book/outputs/scripts/` |

### 4. 反馈迭代层

用途：让体系不是一次性写稿，而是持续变好。

每次输出后记录：

- 哪个概念最容易卡住？
- 哪个例子最有效？
- 哪个误区应该前置？
- 面试追问是否能覆盖真实题库？
- 小红书标题和封面是否有收藏价值？
- 短视频是否能在 5 秒内抛出问题？

反馈来源可以是：

- 自评 Rubric。
- 面试题命中情况。
- 小红书评论、收藏、互动。
- 自己复讲时卡住的位置。
- 竞品内容中高频出现的问题。

## 三、标准生产流程

### Step 1：选一个足够小的知识点

合格选题：

- KV Cache 到底缓存了什么？
- RoPE 为什么能表示相对位置？
- LoRA 为什么只训练两个小矩阵？
- RAG 召回不准怎么排查？

不合格选题：

- 一篇讲完推理优化。
- Transformer 全解析。
- Agent 从入门到精通。

### Step 2：写知识卡

先基于 `src` 笔记写知识卡，禁止直接从 raw 资料生成发布稿。

知识卡是唯一事实底座。后面的讲解稿、面试卡、小红书、视频脚本都要从它派生。

### Step 3：生成讲解稿

讲解稿必须走完整认知链：

```text
问题 -> 直觉 -> 例子 -> 机制 -> 成本/收益 -> 误区 -> 反例 -> 迁移
```

如果是工程知识，要额外补：

- 线上瓶颈在哪里。
- 指标怎么变化。
- 工程取舍是什么。

### Step 4：生成面试卡

面试卡必须包含：

- 30 秒回答。
- 2 分钟回答。
- 常见追问。
- 易错回答。
- 工程延展。

### Step 5：生成内容稿

小红书图文默认结构：

```text
标题候选 -> 封面文案 -> 开头痛点 -> 一句话结论 -> 直觉例子 -> 关键机制 -> 常见误区 -> 面试回答卡 -> 配图建议
```

短视频默认结构：

```text
0-5 秒误区/问题 -> 5-20 秒场景 -> 20-60 秒机制 -> 60-90 秒工程/面试 -> 90-120 秒总结
```

### Step 6：Rubric 自评

每个知识点输出后，使用 `teaching-algorithm-methods/outputs/knowledge-explanation-quality-rubric.md` 打分。

通过标准：

- 总分不低于 85。
- “准确性”“边界/反例”“可讲解性”三个维度都不低于 4 分。
- 如果低于标准，必须记录问题并补一版。

## 四、批量化节奏

建议以“知识点”为最小生产单位，每周做 2-3 个闭环。

优先顺序：

1. 面试高频且容易讲错的知识点。
2. 工程价值高、容易形成收藏内容的知识点。
3. 能串起知识体系的枢纽知识点。

第一批建议：

- KV Cache：推理优化入口。
- Tokenizer：语言模型入口。
- Attention：Transformer 入口。
- LoRA：高效微调入口。
- RAG 评估：应用工程入口。
- Agent 工具调用：Agent 工程入口。
