# 损失函数与交叉熵

## 一句话结论

损失函数是模型学习的“扣分规则”。在语言模型里，交叉熵用来衡量：模型给正确下一个 token 的概率够不够高。

## 1. 为什么需要损失函数

模型训练时并不知道“我讲得好不好”。它只会输出一堆概率，例如：

```text
上下文：我今天很
候选 token 概率：
开心 0.60
难过 0.20
北京 0.01
```

如果真实答案是“开心”，模型应该被鼓励；如果它把“北京”排得很高，就应该被惩罚。损失函数就是把这种好坏变成一个数字，数字越小越好。

## 2. 最大似然的直觉

语言模型训练的目标可以理解为：让训练语料里真实出现的 token 序列概率尽可能大。

一句话：

```text
模型越相信真实答案，训练目标越满意。
```

如果一句话是：

```text
大模型 正在 改变 世界
```

自回归语言模型会依次学习：

- 看到“大模型”，预测“正在”。
- 看到“大模型 正在”，预测“改变”。
- 看到“大模型 正在 改变”，预测“世界”。

每一步都希望正确 token 的概率更高。

## 3. 交叉熵是什么

对单个样本，交叉熵可以写成：

```text
Loss = -log P(正确 token)
```

如果模型给正确 token 的概率是：

| 正确 token 概率 | Loss 直觉 |
| --- | --- |
| 0.9 | 惩罚很小 |
| 0.5 | 惩罚中等 |
| 0.01 | 惩罚很大 |

这就是交叉熵最重要的直觉：模型越不相信正确答案，惩罚越大。

## 4. 为什么要取负 log

直接最大化概率也可以理解，但训练时更常用最小化负对数概率：

```text
最大化 P(正确 token)
等价于
最小化 -log P(正确 token)
```

取 log 有两个好处：

- 把多个 token 的概率相乘变成 log 相加，数值更稳定。
- 对“非常离谱”的错误惩罚更明显。

## 5. 多分类交叉熵

语言模型本质上是在一个很大的词表里做分类。

假设词表有 100000 个 token，每一步模型都输出一个长度为 100000 的概率分布。真实答案只有一个 token，于是交叉熵会检查：真实 token 的概率是多少。

这也是为什么大模型最后通常有一个 `lm_head`：

```text
hidden state -> lm_head -> vocabulary logits -> softmax -> token probability
```

## 6. Perplexity

Perplexity 常被翻译为困惑度，可以理解为交叉熵的指数形式。

直觉上：

- perplexity 越低，模型越不困惑。
- perplexity 越高，模型越拿不准。

但不要把 perplexity 当成唯一指标。一个模型 perplexity 更低，不代表聊天体验、推理能力、工具调用能力一定更好。

## 7. 在 LLM 里的位置

交叉熵会出现在：

- 预训练：预测下一个 token。
- SFT：通常只对 assistant 回复部分算 loss。
- 增量训练：继续用语言建模目标更新模型。
- 蒸馏：学生模型学习教师模型的输出分布。

在偏好对齐里，DPO、PPO、GRPO 不再只是普通交叉熵，但它们仍然建立在“模型给某个输出多大概率”这个基础上。

## 8. 常见误区

### 误区一：loss 低就代表模型好

不一定。loss 更低只能说明它更会拟合某个数据分布。真实应用还要看：

- 指令遵循。
- 事实准确性。
- 推理过程。
- 安全性。
- 工具调用成功率。
- 业务指标。

### 误区二：交叉熵只是在背答案

局部看是在预测 token，整体看是在压缩语言和知识的统计结构。大模型的复杂能力来自大规模数据、模型容量和训练目标共同作用，而不是交叉熵单独产生魔法。

### 误区三：SFT 时所有 token 都应该算 loss

聊天模型训练时，经常只对 assistant 输出算 loss。用户输入和 system prompt 是条件，不一定希望模型去模仿它们。

## 面试追问

### Q1：交叉熵和最大似然是什么关系？

最大化真实 token 的概率，等价于最小化负对数似然；在分类任务中，这个负对数似然就是交叉熵。

### Q2：为什么语言模型用交叉熵？

因为每一步预测都可以看成在词表上的多分类问题，而交叉熵正好衡量模型对正确类别的概率是否足够高。

### Q3：为什么 perplexity 不能代表一切？

perplexity 主要衡量语言建模能力，不直接衡量指令遵循、推理、安全、RAG 忠实性或 Agent 执行成功率。

## 学习检查

学完本章后，应该能独立讲清：

- 为什么 `-log P(正确 token)` 可以当作训练目标。
- 为什么 SFT 常常只对 assistant 回复算 loss。
- 为什么评估 LLM 不能只看 loss 或 perplexity。
