# 第三章：位置编码

## 3.1 为什么需要位置编码？

Transformer 的自注意力机制是**位置无关**的——对输入序列中的每个 token 一视同仁，无论顺序如何变化，输出结果都相同。

```
输入: "狗咬人" vs "人咬狗"

没有位置编码: 两个输入的表示完全相同（只是 token 换了位置）
有位置编码: 两个输入有明显的语义区别
```

### 3.1.1 解决方案

在输入 embedding 上**加上**位置编码：

```python
# 最终输入 = Token Embedding + Position Embedding
final_input = token_embedding + position_embedding
```

## 3.2 绝对位置编码

### 3.2.1 三角函数位置编码（原始 Transformer）

**公式**：

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

其中：
- `pos`: token 在序列中的位置（0, 1, 2, ...）
- `i`: 维度索引（0, 1, 2, ..., d/2）
- `d`: 位置编码的维度（与模型维度相同）

```python
import numpy as np

def get_positional_encoding(seq_len, d_model):
    """生成三角函数位置编码"""
    PE = np.zeros((seq_len, d_model))
    position = np.arange(0, seq_len, dtype=np.float32).reshape(-1, 1)
    div_term = np.exp(np.arange(0, d_model, 2, dtype=np.float32) * 
                       -(np.log(10000.0) / d_model))
    
    PE[:, 0::2] = np.sin(position * div_term)
    PE[:, 1::2] = np.cos(position * div_term)
    
    return PE
```

### 3.2.2 三角函数编码的特点

| 特点 | 说明 |
|------|------|
| **周期性** | 不同频率的正弦/余弦函数可以捕获不同尺度的位置关系 |
| **唯一性** | 每个位置的编码是唯一的 |
| **相对位置** | 可以表示相对位置关系（通过三角函数公式） |

## 3.3 RoPE 旋转位置编码

### 3.3.1 为什么需要 RoPE？

传统位置编码的局限性：
1. **缺乏相对位置信息**：绝对位置编码无法直接表示 token 之间的相对距离
2. **序列长度限制**：训练时有固定长度假设，难以泛化到更长序列
3. **外推问题**：推理时遇到超出训练长度的序列表现差

### 3.3.2 RoPE 核心思想

RoPE（Rotary Positional Embedding）将位置信息编码为**旋转矩阵**，使得：
- 绝对位置编码到旋转
- 注意力分数**自然依赖相对位置**

**数学原理**：

对于位置 m 的 query 向量 x_m，通过旋转矩阵 R_(Θ,m) 变换：

```
RoPE(x_m, m) = x_m * e^(imθ)
```

其中 θ_i = 10000^(-2i/d)

### 3.3.3 RoPE 的优势

1. **相对位置编码**：注意力分数只依赖相对距离 m-n
2. **长上下文外推**：更适合扩展到更长的上下文窗口
3. **高效计算**：可以通过旋转操作高效实现

```python
def apply_rotary_pos_emb(q, k, cos, sin):
    """
    应用 RoPE
    q, k: [batch, heads, seq_len, head_dim]
    cos, sin: [seq_len, head_dim]
    """
    # 将 q, k 分成两半
    q1, q2 = q[..., :q.shape[-1]//2], q[..., q.shape[-1]//2:]
    k1, k2 = k[..., :k.shape[-1]//2], k[..., k.shape[-1]//2:]
    
    # 旋转
    q_rotated = torch.cat([q1 * cos - q2 * sin, q1 * sin + q2 * cos], dim=-1)
    k_rotated = torch.cat([k1 * cos - k2 * sin, k1 * sin + k2 * cos], dim=-1)
    
    return q_rotated, k_rotated
```

### 3.3.4 RoPE vs 传统位置编码

| 特性 | 三角函数编码 | RoPE |
|------|-------------|------|
| **位置信息注入方式** | 加法 | 乘法（旋转） |
| **相对位置编码** | 隐式（通过公式） | 显式（自然包含） |
| **长上下文外推** | 较差 | 较好 |
| **与 Attention 结合** | 加在输入 | 旋转 Q/K 向量 |
| **代表模型** | BERT、T5 | LLaMA、Qwen、GPT |

## 3.4 ALiBi（Attention with Linear Biases）

### 3.4.1 核心思想

不直接在 embedding 中添加位置信息，而是在注意力分数上添加**线性偏置**：

```
Attention(Q, K, V) = softmax(QK^T / √d + α * |i-j|)V
```

其中 |i-j| 是 query i 和 key j 之间的位置距离，α 是可学习的标量。

### 3.4.2 ALiBi 的优势

1. **无需位置编码**：简化了模型
2. **外推性好**：可以处理超出训练长度的序列
3. **距离感知**：注意力自然倾向于近距离 token

---

## 3.5 位置编码对比总结

| 类型 | 优点 | 缺点 | 代表模型 |
|------|------|------|---------|
| **绝对正弦** | 简单、唯一性 | 无相对位置、外推差 | 原始 Transformer |
| **绝对可学习** | 可学习最优编码 | 泛化差、外推差 | BERT |
| **RoPE** | 相对位置、长上下文 | 实现稍复杂 | LLaMA、Qwen |
| **ALiBi** | 天然外推、简单 | 表达能力有限 | MPT、Falcon |
| **相对位置** | 相对位置感知 | 实现复杂 | Shaw et al. |

## 3.6 面试高频问题

### Q1: Transformer 中为什么要用位置编码？

> 自注意力机制本身是位置无关的（permutation invariant），对输入 token 一视同仁。加上位置编码后，模型才能区分不同位置的 token，理解序列顺序。

### Q2: RoPE 和传统位置编码的区别？

> 传统位置编码通过加法将位置信息注入输入；RoPE 通过旋转矩阵对 Q/K 向量进行变换，使得注意力分数自然包含相对位置信息。RoPE 更适合长上下文和长度外推。

### Q3: 为什么需要相对位置编码？

> 很多 NLP 任务中，token 之间的**相对位置**比绝对位置更重要。例如在 "狗咬人" vs "人咬狗" 中，相对位置决定了语义。RoPE 等方法天然支持相对位置建模。

### Q4: 位置编码可以学习吗？

> 可以。另一种常见做法是将位置编码作为可学习参数（Learnable Position Embedding）。但这种方式泛化性较差，训练时没见过长度难以处理。

### Q5: 旋转位置编码如何实现？

> 将 Q/K 向量的维度分成若干组，每组应用不同角度的旋转。旋转角度与位置成正比。计算注意力时，旋转后的向量点积会自然产生与相对位置相关的项。
