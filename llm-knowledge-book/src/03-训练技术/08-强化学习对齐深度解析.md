# 深度解析：强化学习对齐（RLHF/GRPO/DPO）

> 本章内容整理自 GitHub 高质量资源，涵盖 RLHF、DPO、GRPO 等对齐技术的深度解析

---

## 8.1 强化学习基础回顾

### 奖励模型 vs 评判模型

| 维度 | 奖励模型 | 评判模型 |
|------|----------|----------|
| **目的** | 定义任务目标/偏好 | 估计策略的长期价值 |
| **来源** | 外部（环境规则或人类反馈） | 内部（RL训练中学习） |
| **训练** | 在人类偏好数据上预训练 | 与Actor联合训练 |
| **输出** | 即时标量奖励 $r$ | 状态价值 $V(s)$ 或动作价值 $Q(s,a)$ |
| **在RLHF中的角色** | 替代环境奖励信号 | 减少优势估计的方差 |
| **更新** | RL训练期间固定 | 与策略同步更新 |

### 奖励模型训练过程

**目标**：将人类偏好转化为可学习的奖励信号。

**数据构建**：
1. 为同一提示词生成多个候选响应
2. 人工标注者对响应进行排序或成对比较
3. 创建偏好对 $(y^+, y^-)$，其中 $y^+ \succ y^-$

**训练方法（Bradley-Terry模型）**：

$$\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x, y^+, y^-)} \left[\log \sigma\big(r_\phi(x, y^+) - r_\phi(x, y^-)\big)\right]$$

实现：通常使用基础 transformer 加一个线性头，在 [EOS] token 嵌入上输出标量奖励。

### 密集 vs 稀疏奖励

| 奖励类型 | 定义 | 优势 | 挑战 | LLM应用 |
|----------|------|------|------|---------|
| **密集** | 每个token或步骤都有奖励信号 | 收敛更快，梯度更丰富 | 容易奖励作弊，需仔细设计 | 代码生成（逐token语法检查） |
| **稀疏** | 仅在序列末尾给奖励 | 直接对齐真实目标，奖励作弊少 | 训练困难，高方差 | 数学问题（仅正确答案） |
| **混合** | 稀疏最终奖励 + 密集塑形 | 平衡收敛速度和对齐 | 设计复杂 | 生产系统（正确性+风格/格式奖励） |

## 8.2 RLHF/PPO 流水线详解

### 完整 RLHF 流水线

```
SFT模型 → 训练奖励模型（人类偏好数据） → PPO训练（Actor + Critic + 参考模型 + 奖励模型） → 对齐模型
```

### PPO 目标函数

$$L^{\text{PPO}}(\theta) = \mathbb{E}_t \left[ \min \Big( r_t(\theta) A_t, \text{clip}\big(r_t(\theta), 1-\epsilon, 1+\epsilon \big) A_t \Big) \right] + w_1 H(\theta) - w_2 D_{\text{KL}}(\pi_\theta | \pi_{\text{ref}}) - w_3 L_V$$

其中：
- $r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\text{old}}}(a_t|s_t)}$ 是重要性比率
- $A_t$ 是优势函数（通常通过GAE计算）
- $H(\theta)$ 是探索用的熵奖励
- $D_{\text{KL}}$ 是对参考策略的KL散度约束
- $L_V$ 是Critic的价值函数损失

### 各组件作用

| 组件 | 目的 | 缺失后果 |
|------|------|----------|
| **Clip** | 限制每步策略变化 | 训练不稳定，策略崩溃 |
| **KL惩罚** | 防止偏离参考分布 | 语言退化，奖励作弊 |
| **熵奖励** | 鼓励输出多样性 | 过早收敛，模式崩溃 |
| **价值损失** | 训练准确的状态价值估计 | 优势估计高方差，学习缓慢 |

### 广义优势估计（GAE）

$$\hat{A}_t^{\text{GAE}(\gamma, \lambda)} = \sum_{l=0}^\infty (\gamma \lambda)^l \delta_{t+l}$$

其中 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$ 是TD误差。

**参数效果**：
- $\lambda = 0$：纯TD（低方差，高偏差）
- $\lambda = 1$：蒙特卡洛（高方差，低偏差）
- $\lambda = 0.95$（典型值）：平衡折中

### PPO 训练内存需求

| 模型 | 角色 | 可训练 | 内存影响 |
|------|------|--------|----------|
| **Actor** | 生成响应的策略模型 | ✅ 是 | 完整模型 + 梯度 + 优化器状态 |
| **Critic** | 优势估计的价值函数 | ✅ 是 | 完整模型 + 梯度 + 优化器状态 |
| **Reference** | KL散度基线 | ❌ 否 | 完整模型（仅推理） |
| **Reward Model** | 给响应打分 | ❌ 否 | 完整模型（仅推理）或卸载 |

**总计**：内存中需要 4 个模型副本（2个可训练，2个冻结）

### KL散度在PPO中的作用

$$D_{\text{KL}}(\pi_\theta | \pi_{\text{ref}}) = \mathbb{E}_{a \sim \pi_\theta} \left[\log \frac{\pi_\theta(a|s)}{\pi_{\text{ref}}(a|s)}\right]$$

**调参**：
- $\beta$ 太小 → 约束不足，潜在分布崩溃
- $\beta$ 太大 → 过度约束，改进有限
- 典型范围：$\beta \in [0.01, 0.1]$

### PPO：On-Policy vs Off-Policy

PPO 是**近似 on-policy** 的：
- 第一个 mini-batch 更新：on-policy（数据来自当前策略）
- 后续 mini-batch：轻微 off-policy 漂移
- 重要性比率 $r_t(\theta)$ 纠正这种漂移
- Clip 防止过度 off-policy 利用

## 8.3 DPO（直接偏好优化）

### DPO 核心洞察

KL约束奖励最大化下最优策略有闭式解：

$$\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\left(\frac{1}{\beta} r(x,y)\right)$$

重排后奖励可表示为：

$$r(x,y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

代入 Bradley-Terry 偏好模型消去配分函数，得到 DPO 损失。

### DPO 损失函数

$$\mathcal{L}_{\text{DPO}}(\pi_\theta) = -\mathbb{E}_{(x,y_w,y_l)} \left[ \log \sigma \left( \beta \left[ \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right] \right) \right]$$

**直觉**：最大化偏好响应和拒绝响应之间的对数似然比率（相对于参考策略）。

### PPO vs DPO 对比

| 维度 | PPO (RLHF) | DPO |
|------|------------|-----|
| **需要奖励模型** | ✅ 是（单独训练阶段） | ❌ 否 |
| **优化范式** | 强化学习 | 监督学习 |
| **内存需求** | 4个模型（Actor, Critic, Ref, RM） | 2个模型（Policy, Ref） |
| **训练稳定性** | 中等（对超参敏感） | 高 |
| **数据需求** | On-policy采样 + 偏好数据 | 仅偏好对 |
| **灵活性** | 高（支持复杂多目标奖励） | 有限（仅成对偏好） |
| **训练成本** | 高 | 低 |
| **收敛** | 较慢，需仔细调参 | 更快，更稳定 |

### DPO 训练注意事项

1. **参考策略选择**：标准做法使用 SFT 模型作为 $\pi_{\text{ref}}$
2. **β 调参**：控制偏好强度与 KL 约束的权衡，典型范围 [0.1, 0.5]
3. **数据质量**：需要高质量偏好对，模糊的偏好对会损害训练
4. **Choose/Reject Loss 不平衡**：
   - 症状：Choose 损失居高不下（模型无法从正例学习），Reject 损失过低（过度惩罚负例→模式崩溃）
   - 解决方案：长度归一化、调整 β、重加权样本、添加 KL/熵正则化

### DPO 变体

| 变体 | 关键修改 | 优势 | 权衡 |
|------|----------|------|------|
| **IPO** | 恒等映射/标签平滑 | 减少对偏好数据的过拟合 | 可能削弱偏好信号 |
| **KTO** | K路对比（K>2个候选） | 更强判别能力 | 计算成本更高 |
| **CPO** | 保守策略更新 | 更稳定，发散更慢 | 收敛更慢 |
| **IOPO** | 输入-输出联合偏好 | 更好的指令敏感性 | 数据构建复杂 |

## 8.4 GRPO（组相对策略优化）

### GRPO 核心思想

GRPO 通过**消除 Critic 网络**、利用同一提示词多个响应的**组内奖励归一化**来计算优势，从而简化 PPO。

### 数学公式

**1. 采样**：对提示词 $p$，从 $\pi_\theta$ 采样组 $G = \{r_1, r_2, \ldots, r_N\}$

**2. 组内优势**：

$$A_i = \frac{R_\phi(r_i) - \text{mean}(G)}{\text{std}(G)}$$

**3. 裁剪目标**：

$$L_{\text{clip}}(\theta) = \frac{1}{N}\sum_{i=1}^{N} \min\left( \frac{\pi_\theta(r_i|p)}{\pi_{\theta_{\text{old}}}(r_i|p)}A_i, \text{clip}\left( \frac{\pi_\theta(r_i|p)}{\pi_{\theta_{\text{old}}}(r_i|p)}, 1-\varepsilon, 1+\varepsilon \right)A_i \right)$$

**4. 总目标**：

$$L_{\text{GRPO}}(\theta)=L_{\text{clip}}(\theta)-w \cdot D_{\text{KL}}\big(\pi_\theta ,|, \pi_{\text{ref}}\big)$$

注意：GRPO 通常**不使用熵奖励**，因为组采样已提供多样性。

### GRPO vs PPO 对比

| 维度 | PPO | GRPO |
|------|-----|------|
| **优势估计** | 通过Critic/价值函数 $V_\phi(s)$ | 组相对归一化 |
| **额外网络** | 需要 Critic（Actor-Critic） | 不需要 Critic |
| **训练信号** | 带奖励塑形的token级别 | 序列级别组比较 |
| **优势粒度** | 每token（更细粒度信用分配） | 每序列（更粗粒度） |
| **探索机制** | 熵奖励 + on-policy采样 | 组采样多样性 |
| **内存占用** | 更高（4个模型） | 更低（3个模型） |
| **训练复杂度** | 更高 | 更低 |

**直觉类比**：
- **PPO**：老师给每道题打分（细粒度反馈）
- **GRPO**：老师将多份完整作业相对于同龄人平均分排名（粗粒度但高效）

### GRPO 的局限性

1. **无 Critic → 粗粒度优化信号**：仅序列级优势，无 per-token 信用分配
2. **组均匀时无梯度**：所有响应质量相似时 $A_i \approx 0$，整批数据浪费
3. **长度偏差**：较长响应可能累积更多奖励方差
4. **对噪声敏感**：完全依赖组内比较，异常值或噪声提示可能误导训练
5. **有限的长程信用分配**：仅序列级别，对多轮对话或复杂推理链效果较差

### GRPO 在 MoE 模型中的问题

**问题**：重放更新期间的路由不一致性
- 初始采样时：token 分配给专家 A
- 参数更新后：同一 token 可能路由到专家 B
- 打破 PPO/GRPO 的多 epoch 重放假设

**解决方案**：路由缓存、冻结路由器、两阶段更新、使用 GSPO

## 8.5 DAPO 和 GSPO

### DAPO（解耦裁剪与动态采样策略优化）

DAPO 通过四个关键改进增强 GRPO：

$$J_{\text{DAPO}}(\theta) = \mathbb{E}_{(q,a)\sim P(Q), \{o_i\}\sim\pi_{\theta_{\text{old}}}} \left[ \frac{1}{\sum_{i=1}^G |o_i|} \sum_{i=1}^G \sum_{t=1}^{|o_i|} \min\Big( r_{i,t}(\theta)A_i, \text{clip}\big(r_{i,t}(\theta), 1-\epsilon_{\text{low}}, 1+\epsilon_{\text{high}}\big)A_i \Big) \right]$$

| 改进 | 解决的问题 | 解决方案 | 效果 |
|------|-----------|----------|------|
| **(A) 移除KL约束** | KL与长CoT推理冲突 | 消除KL项，仅依赖clip | 聚焦于改善好样本 |
| **(B) 非对称裁剪** | 对称裁剪阻止"不太可能但正确"的token | 更高上界：$[1-\epsilon_{\text{low}}, 1+\epsilon_{\text{high}}]$ | 让罕见正确token能学习 |
| **(C) 动态采样** | 全对或全错组零梯度 | 强制组包含正确和错误响应 | 始终有训练信号 |
| **(D) Token级归一化** | 长序列稀释每token权重 | 按总token数归一化 | 消除长度偏差 |

### GSPO（组序列策略优化）

GSPO 修改 GRPO 使用**序列级重要性比率**而非 token 级，使其对 MoE 架构稳定。

**GSPO 序列级比率**：

$$s_i(\theta) = \left( \frac{\pi_\theta(y_i | x)}{\pi_{\theta_{\text{old}}}(y_i | x)} \right)^{\tfrac{1}{|y_i|}} = \exp\left(\frac{1}{|y_i|} \sum_{t=1}^{|y_i|} \log \frac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t}|x,y_{i,<t})}\right)$$

**GSPO 解决 MoE 路由不稳定的原因**：几何平均平滑路由噪声、单一序列级值减少梯度方差、无需特殊 MoE 处理机制。

### GRPO vs DAPO vs GSPO 总结

| 方法 | 核心创新 | 最适合 | 局限性 |
|------|----------|--------|--------|
| **GRPO** | 组相对优势（无Critic） | 通用高效RL | 长度偏差，均匀组时无梯度 |
| **DAPO** | 非对称裁剪 + token归一化 + 动态采样 | 长形式推理（CoT） | 实现更复杂 |
| **GSPO** | 序列级比率（几何平均） | MoE模型 | 比token级粒度更粗 |

## 8.6 拒绝采样微调（RFT）

### RFT 流程

```
生成多个候选响应 → 奖励模型打分 → 接受 R(y_i) ≥ τ 的样本 → 在接受样本上SFT
```

### RFT vs 统计拒绝采样

| 维度 | 统计拒绝采样 | RFT（LLM语境） |
|------|-------------|----------------|
| **目标** | 从目标分布 $p(x)$ 采样 | 选择高质量输出 |
| **接受准则** | $u \leq \frac{p(x')}{Mq(x')}$ | $R(y_i) \geq \tau$（奖励阈值） |
| **分布保证** | 确保样本精确遵循 $p(x)$ | 无分布保证，偏向高奖励 |
| **目的** | 数学采样正确性 | 训练数据的质量过滤 |

**优势**：比全量 RL 简单、更稳定（仅监督学习）、可解释（基于阈值的过滤）
**劣势**：静态奖励阈值（无动态探索）、需要大样本预算、比 RL 持续改进效率低

## 8.7 训练方法选择矩阵

| 场景 | 推荐方法 | 理由 |
|------|----------|------|
| **初始指令微调** | 全量SFT或LoRA | 构建基础能力 |
| **有限GPU内存（24GB跑7B）** | QLoRA | 4-bit量化+适配器训练 |
| **充足计算的偏好对齐** | PPO (RLHF) | 完整RL灵活性，复杂目标 |
| **有限计算的偏好对齐** | DPO | 无RM训练，无采样，稳定 |
| **无Critic的高效RL** | GRPO | 比PPO简单，组相对优势 |
| **长形式推理（CoT）** | DAPO | 解决长度偏差，非对称裁剪 |
| **MoE架构** | GSPO | 序列级比率，路由稳定 |
| **简单质量过滤** | RFT | 拒绝采样+SFT，无RL复杂度 |

## 8.8 面试高频问题

### Q1: PPO vs DPO 区别？

> **PPO**：需要单独训练奖励模型，4个模型（Actor/Critic/Ref/RM），训练成本高但灵活性强
> **DPO**：无需奖励模型，2个模型，直接在偏好对上优化为监督学习，更稳定高效
> **选择**：计算资源充足且需要复杂奖励 → PPO；资源有限追求稳定 → DPO

### Q2: GRPO 为什么能减少内存？

> GRPO 不需要 Critic 网络（PPO 中 Critic 通常与 Actor 同样大小），因此：
> - PPO 需要 4 个模型：Actor + Critic + Reference + Reward
> - GRPO 只需 3 个模型：Policy + Reference + Reward（无 Critic）
> 内存减少约 25-30%

### Q3: DPO 训练不稳定的常见原因？

> 1. **Choose/Reject Loss 不平衡**：模型无法从正例学习或过度惩罚负例
> 2. **参考策略 $\pi_{\text{ref}}$ 太差**：SFT 模型质量直接影响 DPO 效果
> 3. **偏好对模糊**：模糊的偏好对会误导训练方向
> 4. **β 值不当**：太小导致分布崩溃，太大则改进有限

### Q4: 为什么 DAPO 适合长 CoT 推理？

> 1. **Token 级归一化**：消除长度偏差，长短响应权重相同
> 2. **非对称裁剪**：让罕见但正确的 token 能被学习
> 3. **动态采样**：确保每组都有正负样本，避免零梯度

### Q5: MoE 模型为什么用 GSPO 而不是 GRPO？

> MoE 路由器的随机性导致：
> - 采样时 token 分配给专家 A
> - 更新后同一 token 可能路由到专家 B
> 这打破了 GRPO 的 on-policy 假设
> GSPO 使用序列级几何平均平滑路由噪声
