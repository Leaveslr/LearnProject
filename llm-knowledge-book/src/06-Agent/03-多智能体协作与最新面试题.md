## 一、Multi-Agent 系统概述

### 1.1 为什么需要 Multi-Agent？

```
单 Agent 局限:
- 能力单一，难以处理复杂任务
- 上下文有限，无法持续深入
- 容错性差，单点失败全盘崩溃

Multi-Agent 优势:
- 专业化分工，各有所长
- 并行处理，提升效率
- 去中心化，更强容错
- 涌现能力，1+1>2
```

### 1.2 Multi-Agent 典型场景

| 场景 | Agent 配置 | 协作方式 |
|------|------------|----------|
| 软件开发 | 架构师 + 开发者 + 测试 | 流水线协作 |
| 金融分析 | 数据员 + 分析师 + 报告 | 递进协作 |
| 客服系统 | 路由 + 意图识别 + 问答 | 分工协作 |
| 研究助手 | 搜索 + 阅读 + 总结 + 写作 | 并行+汇总 |
| 游戏 NPC | 多个角色 Agent | 对话协作 |

### 1.3 Agent 能力分级

```
Level 0: 基础响应
  - 纯生成，无工具调用
  - 例: GPT-1

Level 1: 工具使用
  - 调用外部 API/工具
  - 例: GPT-4 + 插件

Level 2: 任务规划
  - 分解复杂任务
  - 例: ReAct Agent

Level 3: 自我反思
  - 评估输出质量
  - 错误时自我修正
  - 例: Reflexion

Level 4: Multi-Agent 协作
  - 多 Agent 分工
  - 通信协作
  - 例: ChatDev, AutoGen

Level 5: 自主学习
  - 从经验中学习
  - 持续自我优化
  - 例: 自我进化 Agent
```

## 二、协作模式与架构

### 2.1 协作模式对比

| 模式 | 说明 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **流水线** | 顺序执行，A→B→C | 简单可靠 | 慢 | 固定流程 |
| **并行** | 同时执行，独立任务 | 快 | 结果整合难 | 独立子任务 |
| **层次** | Supervisor + Workers | 可控 | 依赖上级 | 复杂任务 |
| **网状** | 完全对等通信 | 灵活 | 复杂度高 | 研究探索 |
| **星型** | 中央协调器 | 简单可控 | 中心瓶颈 | 任务分发 |

### 2.2 流水线模式 (Pipeline)

```python
# 软件开发 Multi-Agent 流水线
class SoftwareDevPipeline:
    def __init__(self):
        self.architect = ArchitectAgent()
        self.coder = CoderAgent()
        self.reviewer = ReviewerAgent()
        self.tester = TesterAgent()
    
    def develop(self, requirement):
        # Step 1: 架构设计
        architecture = self.architect.design(requirement)
        
        # Step 2: 代码实现
        code = self.coder.implement(architecture)
        
        # Step 3: 代码审查
        review = self.reviewer.review(code)
        if review.needs_revision:
            code = self.coder.revise(code, review.feedback)
        
        # Step 4: 测试
        test_results = self.tester.test(code, requirement)
        
        return {
            "architecture": architecture,
            "code": code,
            "review": review,
            "tests": test_results
        }
```

### 2.3 层次模式 (Hierarchical)

```python
# 层次化 Multi-Agent
class HierarchicalMultiAgent:
    def __init__(self):
        self.supervisor = SupervisorAgent()
        self.workers = {
            "search": SearchAgent(),
            "analysis": AnalysisAgent(),
            "writing": WritingAgent(),
            "code": CodeAgent(),
        }
    
    def solve(self, task):
        # Supervisor 分析任务并分配
        plan = self.supervisor.decompose(task)
        
        results = {}
        
        for step in plan.steps:
            # 并行执行同层任务
            if step.parallel:
                parallel_results = parallel_execute([
                    (self.workers[name], args) 
                    for name, args in step.tasks
                ])
                results[step.name] = parallel_results
            
            # 顺序执行主任务
            else:
                agent = self.workers[step.agent]
                result = agent.execute(step.args)
                results[step.name] = result
        
        # Supervisor 汇总
        return self.supervisor.synthesize(results)
```

### 2.4 通信协议设计

```python
# Agent 间通信协议
class AgentMessage:
    def __init__(self, sender, receiver, content, msg_type):
        self.sender = sender
        self.receiver = receiver  # "all" 表示广播
        self.content = content
        self.type = msg_type  # request, response, broadcast

class AgentCommunication:
    def send(self, message):
        """发送消息"""
        self.message_queue.put(message)
        logger.info(f"{message.sender} -> {message.receiver}: {message.type}")
    
    def receive(self, agent_id):
        """接收消息"""
        messages = []
        while not self.message_queue.empty():
            msg = self.message_queue.get()
            if msg.receiver in [agent_id, "all"]:
                messages.append(msg)
        return messages
    
    def request_response(self, sender, receiver, content, timeout=30):
        """请求-响应模式"""
        request = AgentMessage(sender, receiver, content, "request")
        self.send(request)
        
        # 等待响应
        start = time.time()
        while time.time() - start < timeout:
            responses = self.receive(sender)
            for resp in responses:
                if resp.type == "response" and resp.sender == receiver:
                    return resp.content
        
        raise TimeoutError(f"Response from {receiver} timed out")
```

## 三、任务分解与规划

### 3.1 任务分解策略

```python
# LLM-based 任务分解
class TaskDecomposer:
    def __init__(self, llm):
        self.llm = llm
    
    def decompose(self, task, mode="auto"):
        if mode == "auto":
            return self._llm_decompose(task)
        elif mode == "template":
            return self._template_decompose(task)
        elif mode == "hierarchical":
            return self._hierarchical_decompose(task)
    
    def _llm_decompose(self, task):
        """使用 LLM 自动分解"""
        prompt = f"""
        任务: {task}
        
        请将任务分解成明确的子任务步骤。
        每个子任务应该:
        1. 有明确的输入和输出
        2. 可独立执行
        3. 有明确的完成标准
        
        输出格式:
        1. [子任务名称]: [描述]
        2. [子任务名称]: [描述]
        ...
        """
        
        response = self.llm.generate(prompt)
        return self._parse_subtasks(response)
    
    def _hierarchical_decompose(self, task, depth=3):
        """层次化分解 (宏观→微观)"""
        if depth == 0:
            return task
        
        # 分解为高阶层任务
        high_level = self.llm.generate(
            f"将 '{task}' 分解为 3-5 个高阶层任务"
        )
        
        # 递归分解每个高阶层任务
        subtasks = []
        for subtask in high_level:
            if self._needs_further_decompose(subtask):
                children = self._hierarchical_decompose(subtask, depth-1)
                subtasks.extend(children)
            else:
                subtasks.append(subtask)
        
        return subtasks
```

### 3.2 规划与执行循环

```python
# Plan-and-Execute 模式
class PlanAndExecuteAgent:
    def __init__(self, planner, executor):
        self.planner = planner
        self.executor = executor
    
    def run(self, task):
        # 1. 制定完整计划
        plan = self.planner.create_plan(task)
        
        # 2. 逐步执行计划
        for step in plan.steps:
            # 执行当前步骤
            result = self.executor.execute(step)
            
            # 3. 检查结果
            if not self._is_satisfactory(result, step):
                # 4. 必要时重新规划
                plan = self.planner.replan(task, result)
            
            # 5. 更新上下文
            self._update_context(step, result)
        
        return self._finalize(plan)
```

### 3.3 反思与自我改进

```python
# Reflexion 自我反思机制
class ReflexionAgent:
    def __init__(self, agent, threshold=0.7):
        self.agent = agent
        self.threshold = threshold
    
    def run(self, task):
        max_attempts = 3
        history = []
        
        for attempt in range(max_attempts):
            # 执行任务
            result = self.agent.execute(task)
            history.append(result)
            
            # 自我评估
            score = self._self_evaluate(task, result)
            
            if score >= self.threshold:
                return result
            
            # 生成反思
            reflection = self._reflect(task, result, history)
            
            # 带着反思重新执行
            task = f"{task}\n\n反思: {reflection}"
        
        # 返回最佳结果
        return max(history, key=lambda x: self._self_evaluate(task, x))
    
    def _self_evaluate(self, task, result):
        """LLM 自我评估"""
        prompt = f"""
        任务: {task}
        结果: {result}
        
        评估结果的质量 (0-1):
        - 0: 完全不正确
        - 0.5: 部分正确
        - 1: 完全正确
        
        评分及理由:
        """
        response = self.llm.generate(prompt)
        return self._parse_score(response)
    
    def _reflect(self, task, result, history):
        """生成反思"""
        prompt = f"""
        任务: {task}
        结果: {result}
        历史尝试: {history}
        
        分析失败原因，并给出改进建议:
        """
        return self.llm.generate(prompt)
```

## 四、Agent 面试实战题

### 4.1 概念理解题

#### Q1: 什么是 ReAct 范式？它解决了什么问题？

**参考答案**:

ReAct = **Re**asoning + **Act**ing

**核心思想**: 让 LLM 交替进行推理和行动

```
思考 (Thought) → 行动 (Action) → 观察 (Observation) → ...
```

**解决的问题**:
1. **推理链断裂**: LLM 单纯推理时没有外部信息
2. **幻觉问题**: 通过工具获取真实信息
3. **任务执行**: 不仅思考，还能真正"做事"

**与 CoT 的区别**:
- CoT: 仅推理，不行动
- ReAct: 推理 + 行动 + 观察

```python
# ReAct 示例
question = "iPhone 15 的续航是多少？"
# Thought: 我需要搜索 iPhone 15 的续航信息
# Action: search[iPhone 15 battery life]
# Observation: iPhone 15 续航最长可达20小时
# Thought: 用户问的应该是视频播放续航
# Action: finish[最长20小时视频播放]
```

#### Q2: Tool Agent 和 Multi-Agent 的区别是什么？

**参考答案**:

| 维度 | Tool Agent | Multi-Agent |
|------|------------|-------------|
| **主体** | 单 Agent | 多 Agent |
| **工具** | Agent 调用工具 | Agent 间相互调用 |
| **通信** | Agent → 工具 | Agent ↔ Agent |
| **复杂度** | 较低 | 高 |
| **适用** | 简单任务 | 复杂协作任务 |

**关系**: Multi-Agent 通常包含 Tool Agent，每个 Agent 可以调用工具

#### Q3: 什么是指令遵循 (Instruction Following)？

**参考答案**:

**定义**: 模型准确理解和执行用户指令的能力

**评估维度**:
1. **理解准确性**: 正确解析指令意图
2. **格式遵循**: 按要求格式输出
3. **约束遵守**: 满足指定条件
4. **完整性**: 完成所有要求

**相关概念**:
- **CoT (Chain of Thought)**: 展示推理过程
- **ToT (Tree of Thought)**: 探索多种推理路径
- **RLHF**: 通过强化学习提升指令遵循

### 4.3 技术细节题

#### Q6: 如何实现 Agent 的断点恢复？

**参考答案**:

```python
class CheckpointAgent:
    def __init__(self, checkpoint_store):
        self.checkpoint_store = checkpoint_store
        self.state = {}
    
    def save_checkpoint(self, session_id, step, state):
        """保存检查点"""
        checkpoint = {
            "session_id": session_id,
            "step": step,
            "state": state,
            "timestamp": time.time()
        }
        self.checkpoint_store.save(checkpoint)
    
    def restore(self, session_id):
        """恢复检查点"""
        checkpoint = self.checkpoint_store.load(session_id)
        if checkpoint:
            self.state = checkpoint["state"]
            return checkpoint["step"]
        return 0
    
    def run_with_checkpoint(self, task, session_id):
        """带检查点的执行"""
        start_step = self.restore(session_id)
        
        for step in range(start_step, self.max_steps):
            # 执行步骤
            result = self.execute_step(step)
            self.state.update(result)
            
            # 保存检查点
            if step % 5 == 0:  # 每5步保存
                self.save_checkpoint(session_id, step, self.state)
            
            # 检查是否完成
            if self.is_complete():
                return self.state
        
        return self.state
```

#### Q7: Agent 的 Token 消耗如何优化？

**参考答案**:

```
优化策略:

1. Prompt 压缩
   - 删除冗余描述
   - 使用缩写
   - 关键信息提取

2. 上下文管理
   - 对话历史截断
   - 摘要替换完整历史
   - 重要信息提取

3. 工具调用优化
   - 批量处理
   - 缓存结果
   - 避免重复调用

4. 响应压缩
   - 结果摘要
   - 选择性返回
```

```python
# 上下文压缩示例
def compress_history(messages, max_tokens=4000):
    """压缩对话历史"""
    if count_tokens(messages) <= max_tokens:
        return messages
    
    # 保留系统 prompt 和最近消息
    system = [m for m in messages if m.role == "system"]
    recent = messages[-10:]  # 最近10条
    
    # 中间部分摘要
    middle = messages[len(system):-10]
    if middle:
        summary = llm.summarize(
            f"总结以下对话要点:\n{format_messages(middle)}"
        )
        return system + [summary] + recent
    
    return system + recent
```
