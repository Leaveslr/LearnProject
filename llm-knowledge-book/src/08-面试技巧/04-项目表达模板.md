# LLM 项目表达模板

## 一句话结论

LLM 项目面试不能只讲“我用了 RAG / Agent / 微调”，要讲清楚业务问题、技术方案、指标提升、失败案例和取舍。

## 1. 项目表达总结构

推荐按这个顺序讲：

```text
背景 -> 问题 -> 方案 -> 难点 -> 指标 -> 失败案例 -> 复盘
```

每个项目都要准备 3 个版本：

- 30 秒版本：自我介绍或快速概述。
- 2 分钟版本：常规项目介绍。
- 10 分钟版本：深挖技术细节。

## 2. 30 秒版本

模板：

```text
我做的是一个【业务场景】里的【LLM/RAG/Agent/微调】项目，目标是解决【核心问题】。
我主要负责【你的职责】，方案上采用了【关键技术】。
最终在【指标】上从【baseline】提升到【结果】，同时解决了【一个关键难点】。
```

示例：

```text
我做的是企业知识库问答里的 RAG 项目，目标是降低客服查资料成本。
我主要负责检索链路和评估体系，方案上采用了文档清洗、混合检索、rerank 和引用溯源。
最终 top-5 召回率从 72% 提升到 88%，人工验收通过率从 65% 提升到 81%，同时解决了多版本文档引用混乱的问题。
```

## 3. 2 分钟版本

模板：

```text
背景：
业务里原来怎么做，为什么效率或效果不好。

问题：
核心技术问题是什么，例如召回不足、幻觉、延迟高、成本高、工具调用失败。

方案：
你用了哪些模块，每个模块解决什么。

难点：
最难的不是“接 API”，而是某个真实约束，例如数据脏、权限复杂、评估难、长尾问题多。

指标：
给出 baseline、改进后结果和评估方法。

复盘：
讲一个失败案例，以及你如何定位和修复。
```

## 4. RAG 项目追问准备

必须准备：

- 文档怎么解析和清洗？
- chunk size 怎么定？
- embedding 模型怎么选？
- 为什么要 hybrid search？
- rerank 放在哪一层？
- golden set 怎么构造？
- 如何判断错在检索还是生成？
- 如何做引用溯源？
- 如何处理无答案问题？
- 如何控制权限？

不要只回答“用了向量数据库”。要能说清楚每个选择背后的指标。

## 5. Agent 项目追问准备

必须准备：

- 为什么需要 Agent，而不是 workflow？
- 工具有哪些，schema 怎么设计？
- 工具调用失败怎么办？
- 如何避免死循环？
- memory 存什么，不存什么？
- 哪些步骤需要 human-in-the-loop？
- trace 怎么记录？
- Agent eval 怎么做？
- 成本和延迟怎么控制？
- 安全边界在哪里？

重点：Agent 项目一定要讲“可控性”，不要只讲“自动化”。

## 6. 微调项目追问准备

必须准备：

- 为什么不用 prompt 或 RAG？
- 数据从哪里来？
- 数据质量怎么控制？
- SFT 还是 LoRA？
- loss mask 怎么做？
- rank、learning rate、epoch 怎么选？
- 如何避免过拟合？
- 评估集怎么构造？
- 线上效果和离线指标是否一致？
- 是否出现能力退化？

重点：微调项目要讲清楚“为什么值得改参数”。

## 7. 推理部署项目追问准备

必须准备：

- 模型大小和硬件配置。
- TTFT、TPOT、吞吐、并发。
- 是否使用 vLLM / SGLang / TensorRT-LLM。
- 是否量化，为什么选这种量化。
- KV Cache 显存怎么算。
- 如何处理长上下文。
- 如何压测。
- 如何降成本。
- 如何监控线上异常。

重点：部署项目要有数字，没有数字就很难体现工程能力。

## 8. 指标表达

指标要尽量成对出现：

```text
baseline -> 改进后
```

常见指标：

- 召回率。
- 人工验收通过率。
- 答案正确率。
- 忠实性。
- 工具调用成功率。
- 任务完成率。
- TTFT。
- TPOT。
- tokens/s。
- 单请求成本。

不要只说“效果提升明显”。

## 9. 失败案例模板

模板：

```text
上线前我们发现【现象】。
一开始怀疑是【初始假设】，后来通过【排查方法】发现真正原因是【根因】。
我们做了【修复方案】，最后【指标】从【前】变成【后】。
这个问题让我意识到【复盘】。
```

示例：

```text
上线前我们发现部分制度问答会引用旧版本文档。
一开始怀疑是模型幻觉，后来通过查看检索结果发现旧文档被召回且排序更靠前。
我们给文档增加版本字段，在检索阶段过滤过期版本，并在 rerank 特征里加入时效性。
修复后旧文档误引用率从 18% 降到 3%。
```

## 10. 面试官最想听什么

面试官通常不只想听技术名词，而是判断：

- 你是否真的做过。
- 你是否知道方案为什么有效。
- 你是否知道哪里会失败。
- 你是否能量化效果。
- 你是否能在约束下做取舍。
- 你是否能把经验迁移到新问题。

## 学习检查

每个项目至少准备：

- 1 个 30 秒版本。
- 1 个 2 分钟版本。
- 5 个技术追问。
- 3 个指标。
- 1 个失败案例。
- 1 个后续优化方向。
