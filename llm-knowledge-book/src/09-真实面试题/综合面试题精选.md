## 一、模型架构类面试题

### Q1: Transformer 为什么需要位置编码？

**答案要点**：

1. **Self-Attention 本身不包含位置信息**
   - Self-Attention 计算：$Attention(Q, K, V) = softmax(\frac{QK^T}{\sqrt{d_k}})V$
   - 这个公式对输入序列是置换不变的（permutation invariant）
   - "我爱你" 和 "你爱我" 会得到完全相同的表示

2. **位置编码的作用**
   - 为序列中的每个位置分配一个独特的编码
   - 让模型能够区分不同位置的 token
   - 使 Transformer 具备处理序列数据的能力

3. **常见位置编码对比**

| 位置编码 | 公式 | 优点 | 缺点 |
|----------|------|------|------|
| **绝对位置编码 (Sinusoidal)** | $PE_{(pos,2i)} = sin(pos/10000^{2i/d})$ | 可外推、支持相对距离 | 难以学习相对位置 |
| **相对位置编码 (RoPE)** | 在 Attention 中引入相对偏移 | 更自然地捕捉距离关系、长上下文友好 | 实现复杂 |
| **ALiBi** | 在 Attention 分数上加线性偏置 | 无需学习、外推性好 | 影响精度 |

### Q2: RoPE 旋转位置编码原理？

**答案要点**：

1. **核心思想**：通过旋转矩阵将位置信息融入 Query 和 Key

2. **数学原理**：
   - 对位置 $m$ 的 Query 向量 $q_m$ 进行旋转：
   - $q'_m = R_m q_m$
   - 其中 $R_m = \begin{pmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{pmatrix}$

3. **为什么有效**：
   - 两个位置 $m,n$ 的注意力：$q'_m \cdot k'_n = (R_m q_m)^T (R_n k_n) = q_m^T R_m^T R_n k_n$
   - $R_m^T R_n = R_{n-m}$ 只依赖相对位置 $n-m$
   - 自然地捕捉相对位置关系

4. **LLM 中的应用**：
   - LLaMA、Qwen、GLM 等主流模型都使用 RoPE
   - 配合 RoPE 外推技术（位置插值、YaRN 等）可支持超长上下文

### Q3: Flash Attention 为什么能加速？

**答案要点**：

1. **标准 Attention 的问题**：
   - 需要计算完整的 $S = QK^T$ 矩阵（$O(n^2)$ 显存）
   - $N=4096$ 时，$QK^T$ 需要 64MB（FP16）
   - 无法处理长序列

2. **Flash Attention 的核心**：
   - **分块计算**：不一次性计算完整 Attention
   - **在线 softmax**：分块计算时也能得到正确结果
   - **IO 感知**：减少 GPU HBM 和 SRAM 之间的数据移动

3. **性能收益**：
   - 显存从 $O(n^2)$ 降到 $O(n)$
   - 速度提升 2-4 倍
   - 首次让 100K+ 序列成为可能

4. **实现原理**：
```python
# 伪代码展示分块计算
for i in range(0, n, block_size):
    # 加载一块 Q
    Qi = load_Q(i)
    
    # 计算局部注意力
    S_block = Qi @ K[:i+block_size].T
    Mi, Pi = online_softmax(S_block, m_prev, P_prev)
    
    # 更新统计量
    m_prev, P_prev = update(Mi, Pi)
```

## 二、训练技术类面试题

### Q4: 为什么 SFT 后还要 RLHF？

**答案要点**：

1. **SFT 的局限性**：
   - SFT 只能模仿训练数据的分布
   - 无法优化"主观偏好"（如对话风格、礼貌程度）
   - 在安全性和有用性之间难以平衡

2. **RLHF 能做到什么**：
   - 直接优化人类偏好（Helpful, Honest, Harmless）
   - 在安全性达标的同时保持有用性
   - 能发现训练数据中不存在但更优的响应策略

3. **典型案例**：
   - InstructGPT 显示 RLHF 后人类评估显著提升
   - ChatGPT 的对话流畅性和安全性很大程度上来自 RLHF

### Q5: DPO 和 PPO 怎么选？

**答案要点**：

| 维度 | PPO (RLHF) | DPO |
|------|------------|-----|
| **适用场景** | 计算资源充足、复杂多目标奖励 | 资源有限、快速迭代 |
| **训练稳定性** | 中等（需调参） | 高（更稳定） |
| **内存需求** | 高（4个模型） | 低（2个模型） |
| **效果上限** | 更高（更灵活） | 略低但足够 |

**建议**：
- 生产环境追求稳定 → DPO
- 学术研究追求极限 → PPO
- 实际工程中 DPO 更常用

### Q6: LoRA 为什么用低秩矩阵？

**答案要点**：

1. **理论基础**：
   - 论文《LoRA: Low-Rank Adaptation》证明：模型适配过程中参数改变量 $\Delta W$ 具有低秩特性
   - 即 $\Delta W$ 可以近似分解为两个小矩阵的乘积

2. **数学表示**：
   $$W' = W + \Delta W \approx W + BA$$
   其中 $B \in \mathbb{R}^{d \times r}$，$A \in \mathbb{R}^{r \times k}$，$r \ll \min(d,k)$

3. **参数量对比**：
   - 全量微调：$O(d \times k)$
   - LoRA：$O(r \times (d + k))$
   - 如果 $r=8, d=k=4096$，则参数量从 16M 降到 65K（250倍压缩）

4. **为什么有效**：
   - 预训练模型已学习到通用知识
   - 下游任务只需微调少量方向
   - 这些方向通常位于低维子空间

## 三、推理优化类面试题

### Q7: 量化损失精度怎么控制？

**答案要点**：

1. **选择合适的量化方法**：
   - INT8：精度损失 <1%，通常无感知
   - INT4：精度损失 2-5%，需要校准

2. **关键因素**：
   - **校准数据质量**：覆盖目标分布的 512-1024 个样本
   - **量化粒度**：逐通道 > 逐张量
   - **量化方法**：AWQ > GPTQ > 朴素量化

3. **AWQ 的核心思想**：
   - 不是所有权重都同等重要
   - 按激活值判断重要性，保护"重要"权重
   - 4-bit 量化效果接近 FP16

4. **验证流程**：
```python
# 量化后必须验证
def validate_quantization(model, calibration_data):
    original_outputs = model(calibration_data)
    quantized_outputs = quantized_model(calibration_data)
    
    # 计算输出相似度
    similarity = cosine_similarity(original_outputs, quantized_outputs)
    assert similarity > 0.95, "量化精度损失过大"
```

### Q8: vLLM 为什么快？

**答案要点**：

1. **PagedAttention**：
   - 将 KV Cache 分块管理，避免显存碎片
   - 类似操作系统的虚拟内存分页
   - 显存利用率从 30% 提升到 90%+

2. **Continuous Batching**：
   - 动态批处理，多请求共享 GPU
   - 请求完成立即释放，其他请求加入
   - GPU 利用率显著提升

3. **其他优化**：
   - CUDA 核心融合
   - 异步执行
   - 前缀缓存

4. **性能对比**：
   - Throughput：比 HF 高 10-30 倍
   - 首 Token 延迟：相近或略低
   - 吞吐延迟平衡最好

### Q9: Tensor Parallelism 怎么切分？

**答案要点**：

1. **张量并行原理**：
   - 按模型维度切分到多卡
   - 每卡计算部分结果
   - AllReduce 汇总

2. **Embedding 和 Output Linear**：
   - 按词表维度切分（Column Parallel）
   - 各卡存储部分词向量
   - 输出时 AllReduce

3. **Attention**：
   - 按 head 切分（Multi-Head Parallel）
   - 或按 hidden 维度切分（Tensor Parallel Attention）

4. **MLP**：
   - 第一个 Linear：Column Parallel
   - 第二个 Linear：Row Parallel
   - 需两次 AllReduce

5. **通信量估算**：
   - 每个 Transformer 层：2 次 AllReduce
   - 一次 AllReduce：$2 \times \text{张量大小}$ bytes
   - TP=8 比 TP=4 通信量翻倍

## 四、应用技术类面试题

### Q10: RAG 怎么提升召回率？

**答案要点**：

1. **多路检索**：
   - 向量检索（语义相似）
   - BM25（关键词匹配）
   - 混合加权组合

2. **查询优化**：
   - 查询扩展：用 LLM 改写查询
   - HyDE：用 LLM 生成假设答案再检索
   - 意图识别：根据意图选择检索策略

3. **Embedding 优化**：
   - 用领域数据微调 Embedding
   - 大模型（e5、bge）效果更好
   - 按场景选择合适模型

4. **重排序**：
   - 先向量检索 Top-100
   - 再 Cross-Encoder 精排 Top-10

### Q11: Agent 如何避免循环？

**答案要点**：

1. **预算控制**：
   - 最大步数限制（如 10 步）
   - 最大 API 调用次数
   - 最大时间预算

2. **状态追踪**：
   - 记录已访问的 URL、已查询的工具
   - 避免重复执行相同操作
   - 工具调用去重

3. **终止判断**：
   - LLM 判断是否继续
   - 置信度阈值触发停止
   - 结果质量评估

4. **熔断降级**：
   - 连续失败 N 次自动降级
   - 回退到简单方案
   - 优雅提示用户

### Q12: 如何评估 Agent 效果？

**答案要点**：

1. **任务完成率**：
   - 成功完成任务的比例
   - 按任务类型分组

2. **效率指标**：
   - 平均步数/工具调用数
   - 平均延迟
   - 成本消耗

3. **质量指标**：
   - 最终答案正确性
   - 中间步骤合理性
   - 工具选择准确性

4. **鲁棒性指标**：
   - 失败恢复能力
   - 异常输入处理
   - 边界情况覆盖

## 五、综合类面试题

### Q13: 面试中被问到"你了解哪些前沿技术"怎么回答？

**建议结构**：

1. **模型架构**：RoPE、MoE、GQA、MLA
2. **训练技术**：GRPO、DPO、QLoRA
3. **推理优化**：Flash Attention、PagedAttention、投机解码
4. **应用系统**：RAG、Agent、多模态

**回答示例**：
> "最近比较关注几个方向：
> 
> 一是推理优化，像 Flash Attention 和 PagedAttention 已经比较成熟，新的是投机解码（Speculative Decoding），用小模型猜、大模型验证，能在保持质量的同时提速 2-3 倍。
> 
> 二是训练效率，LoRA 和 QLoRA 已经广泛使用，最近在关注 GRPO 和 DAPO 这些新的对齐方法，在长 CoT 场景下效果更好。
> 
> 三是 Agent 系统架构，特别是多模态 Agent 和长期记忆管理这块，觉得是未来落地的重点。"

### Q14: "你遇到过最难的 bug 是什么"怎么回答？

**STAR 法则**：
- **Situation**：描述背景
- **Task**：明确任务
- **Action**：采取的行动
- **Result**：取得的结果

**示例回答**：
> "有一次在部署量化模型时遇到了精度问题。
> 
> 任务是用 INT4 量化部署一个 70B 的模型，但上线后发现回答质量明显下降，特别是数学推理类的题目错得很多。
> 
> 我先排查了量化过程，确认校准数据没有问题。然后用 Perplexity 评估发现模型困惑度只增加了 2%，说明量化本身没问题。
> 
> 最后发现是量化后的模型在特定温度参数下表现异常，调整 temperature 后问题解决。
> 
> 这个经历让我认识到：量化评估不能只看 perplexity，必须在实际部署场景下测试。"
