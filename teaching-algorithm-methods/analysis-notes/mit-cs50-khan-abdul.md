# 算法课程样本分析：MIT / CS50 / Khan Academy / Abdul Bari

## 共同特点

- 都不会只给定义，而是先制造一个“需要算法”的场景。
- 都使用小例子让学习者能手动模拟算法过程。
- 严谨课程会在直觉之后补充边界、复杂度和正确性。
- 视频讲解通常比文字教程更依赖节奏：停顿、重复、画图、擦除和重新组织。

## Khan Academy：初学者路径最清晰

讲解结构：

1. 用一句话定义算法用途。
2. 用已有经验类比，例如猜数字。
3. 用大规模例子制造效率差异，例如星表搜索。
4. 逐步补齐算法描述：输入、输出、变量、循环。
5. 再进入实现、挑战题和运行时间。

值得复用：

- “先人话，后代码”的顺序很稳。
- 先讲“合理猜测范围”，再讲 `low/high/mid`，变量就不再突兀。
- 练习紧跟讲解，避免学生停留在看懂。

## MIT 6.006：严谨性和主题编排

讲解结构：

1. 给出问题模型。
2. 明确算法策略。
3. 分析正确性和复杂度。
4. 通过 recitation、problem set、代码材料巩固。

值得复用：

- 对进阶内容，必须明确“问题模型”是什么；否则学生会把算法误用到不满足条件的场景。
- 复杂度不要孤立讲，要和算法的关键动作绑定：减半、合并、遍历边、松弛等。
- 课程级组织需要从基本思想到数据结构，再到图、动态规划等抽象层级。

## CS50：生活化演示和舞台感

讲解结构：

1. 用真实物件或生活动作演示，例如电话簿、排序人群。
2. 让学生先看到“笨办法”和“聪明办法”的差异。
3. 再命名算法和复杂度符号。

值得复用：

- 初学者对符号没有感情，但对“做很多重复劳动”有感觉。
- 可以先演一个低效流程，再演一个高效流程，最后才说 Big-O。
- 讲抽象概念时，身体动作、物件和空间位置能形成记忆锚点。

## Abdul Bari：板书式手推与伪代码节奏

讲解结构：

1. 板书列出输入或问题条件。
2. 手动走一遍核心过程。
3. 写伪代码。
4. 分析时间/空间复杂度。
5. 补充特殊情况或递归树。

值得复用：

- 对排序、图、动态规划等过程型算法，手推比先讲定义更有效。
- 伪代码要出现在学习者已经看过过程之后。
- 板书式讲解的优势是“每一步都留痕”，学习者能看到思考轨迹。

## 可抽象出的算法讲解动作

- 先问：如果不用这个算法，你会怎么做？
- 再问：这个做法慢在哪里？
- 给一个能手算的小输入。
- 固定一个状态表示，例如“合理范围”“已排序区”“当前节点集合”。
- 每一步只改变一个状态，别同时讲变量、循环、复杂度。
- 代码前先给伪代码或自然语言步骤。
- 复杂度要从“关键动作重复了几次”推出来。
