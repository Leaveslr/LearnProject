# 流程走样例：Agent 工具调用

## 目标

把 Agent 工具调用讲成“受约束的行动循环”，而不是只讲 function calling。

## 1. 问题场景

很多任务不是回答一句话就结束，而是要查数据、算结果、写文件、调用业务系统，并根据结果继续下一步。

## 2. 直觉模型

```text
理解任务 -> 选择工具 -> 填参数 -> 执行 -> 观察结果 -> 决定下一步
```

Agent 强在循环和反馈，不只是多了工具列表。

## 3. 最小例子

任务：“查今天销售额，并和昨天比。”

1. 调数据库工具查今天销售额。
2. 查昨天销售额。
3. 调计算逻辑算环比。
4. 输出结论和异常说明。

## 4. 机制拆解

- Tool registry：工具名、描述、参数 schema、返回格式。
- Planner/Policy：决定下一步用什么工具。
- Executor：执行工具并拿 observation。
- State/Trace：保存中间过程。
- Guardrail：权限、次数、成本、人工确认。

## 5. 工程取舍

- 简单固定流程优先 workflow。
- 不确定、多分支任务才需要更强 Agent。
- 高风险动作必须 human-in-the-loop。

## 6. 易错点和反例

- 错误：有 function calling 就是 Agent。反例：单次工具调用没有循环规划。
- 错误：工具越多越好。反例：工具描述相似会增加误调用。
- 错误：只看最终答案。反例：中间越权调用也算失败。

## 7. 迁移练习

- 给天气查询工具写 schema。
- 工具返回空结果时，Agent 应该怎么恢复？
- 什么场景必须让人确认后再执行？
