# 验证案例：二分查找

## 目标

验证知识拆解框架是否能把二分查找讲给编程初学者。

## 讲解大纲

### 问题场景

在一个有序名单里找某个名字。朴素做法是从头到尾一个个看，最坏情况下要看完整个名单。

### 已有经验

猜数字游戏：如果猜 50，对方说太大，那么 50 以上都不用再猜。

类比边界：猜数字能成立，是因为数字有大小顺序；二分查找也要求数据有序。

### 直觉模型

二分查找维护的是“答案还可能存在的范围”。每次看中间元素，根据大小关系排除一半。

### 手算

数组：`[2, 5, 8, 12, 16, 23, 38]`，目标：`16`

1. 范围是全部元素，中间是 `12`。
2. `16 > 12`，所以左半边和 `12` 都不可能是答案。
3. 新范围是 `[16, 23, 38]`，中间是 `23`。
4. `16 < 23`，所以右半边和 `23` 都不可能是答案。
5. 新范围是 `[16]`，找到目标。

### 最小形式化

- 输入：有序数组、目标值。
- 输出：目标值的位置，或不存在。
- 状态：`left`、`right`、`mid`。
- 不变量：如果目标存在，它一定在 `left..right` 范围内。

### 易错点

- 忘记数组必须有序。
- `left <= right` 和 `left < right` 的循环条件混用。
- `mid` 计算和边界更新导致死循环。
- 找“任意一个目标”与找“第一个大于等于目标”的规则不同。

### 复杂度

每次把范围减半。长度从 `n` 变成 `n/2`、`n/4`、`n/8`，直到 1，所以次数是 `log n` 级别。

## 验证结论

该框架适合二分查找，因为它能自然突出前置条件、有序性、不变量、边界更新和复杂度来源。
