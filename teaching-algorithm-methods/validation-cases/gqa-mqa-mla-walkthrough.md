# 流程走样例：MHA / MQA / GQA / MLA

## 目标

从 KV Cache 成本出发，讲清多头注意力变体为什么存在。

## 1. 问题场景

MHA 表达能力强，但每个 Q 头都有独立 K/V。推理时历史 K/V 要缓存，长上下文下显存压力大。

真人口播开场：

> 这一组缩写 MHA、MQA、GQA、MLA，看起来很像考试专门折磨人的名词。但你别先背名字，先抓住一个问题：推理时历史 K/V 要放进 KV Cache，如果每个头都各存一份，显存很快就会顶不住。后面这些变体，本质上都是在问：K/V 能不能少存一点？

## 2. 直觉模型

- MHA：每个小组一份资料。
- MQA：所有小组共用一份资料。
- GQA：几个小组共用一份资料。
- MLA：先压缩成低维笔记，需要时再展开。

## 3. 最小例子

```text
32 个 Q 头
MHA: 32 组 KV
MQA: 1 组 KV
GQA: 8 组 KV
MLA: 缓存低维 latent
```

## 4. 机制拆解

KV Cache 近似正比于 `num_kv_heads`。

自然转场：

> 所以这节课的钥匙不是 Q 头，而是 KV 头。你只要盯住“到底存了几组 K/V”，这些缩写就会清楚很多。

- MHA：`num_kv_heads = num_q_heads`。
- MQA：`num_kv_heads = 1`。
- GQA：`1 < num_kv_heads < num_q_heads`。
- MLA：不直接缓存完整 KV，而缓存压缩 latent。

## 5. 工程取舍

- MQA 最省，但可能牺牲表达。
- GQA 是现代 LLM 常见折中。
- MLA 更进一步压缩，但实现复杂。

## 6. 易错点和反例

- 错误：GQA 减少 Q 头。实际是减少 KV 头。
- 错误：MQA 一定最好。极致共享可能影响质量。
- 错误：MLA 就是 GQA 换名字。MLA 关键是低秩压缩缓存。

卡点提醒：

> 如果你分不清 MQA 和 GQA，就用一句话压住：MQA 是“所有人共用一份资料”，GQA 是“几个人一组共用一份资料”。它们不是为了名字好看，而是为了让 KV Cache 少一点。

## 7. 迁移练习

- 32 Q 头、8 KV 头，每几个 Q 头共享一组 KV？
- 为什么长上下文模型更关心 KV 头数？
- GQA 和 KV Cache 公式怎么对应？

真人收束句：

> 所以这题面试时别散着答。先说 KV Cache 太大，再说减少 KV 头，最后按 MHA、MQA、GQA、MLA 讲取舍，逻辑就顺了。
