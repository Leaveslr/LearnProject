# 流程走样例：LoRA

## 目标

把 LoRA 讲成“低秩权重增量”，而不是只说参数高效。

## 1. 问题场景

全参数微调要更新完整权重矩阵，显存高、训练慢、每个任务保存成本大。

真人口播开场：

> LoRA 这个词听起来很工程，但它解决的问题其实特别朴素：我只是想让模型适应一个新任务，真的有必要把整个大模型都改一遍吗？就像一本书已经写得很好了，我只是想在旁边贴几张补充说明，不一定要重写整本书。

LoRA 解决的是：能不能不动原模型，只学一小部分任务相关变化。

## 2. 直觉模型

原模型是一本大书。全参微调是改整本书，LoRA 是贴任务补丁页。

边界：补丁页适合小范围适配，不一定能重写整本书的知识结构。

## 3. 最小例子

```text
W_new = W0 + Delta W
LoRA: Delta W = B * A
A: r*k
B: d*r
r << d,k
```

## 4. 机制拆解

1. 冻结 `W0`。
2. 训练小矩阵 `A/B`。
3. 前向时加上 `alpha/r * B*A`。
4. 推理时可合并，也可加载 adapter。

自然转场：

> 到这里你会发现，LoRA 的重点不是“小”，而是“只学变化”。原来的大模型能力还在，LoRA 学的是这个任务需要往哪个方向推一把。

## 5. 工程取舍

- 优点：显存低、保存小、切换快。
- 代价：能力上限可能低于全参微调。
- QLoRA：基础模型量化，LoRA 参数训练，进一步省显存。

## 6. 易错点和反例

- 错误：LoRA 是训练一个小模型。实际是给大模型加低秩增量。
- 错误：r 越大越好。r 大会增加参数和过拟合风险。
- 错误：LoRA 适合所有任务。大规模知识注入可能不够。

卡点提醒：

> 很多人会把 LoRA 说成“省显存技巧”，这没错，但不够。你还要说出它为什么能省：完整的 `Delta W` 太大，所以用两个低秩矩阵去近似这个变化。

## 7. 迁移练习

- 为什么 B 常用零初始化？
- LoRA target modules 选错会怎样？
- LoRA 和 prompt tuning 都是 PEFT，它们差在哪？

真人收束句：

> 所以面试里讲 LoRA，最稳的顺序是：全参微调太贵，权重变化可低秩近似，冻结原模型，只训练 A/B，最后再讲 QLoRA 怎么进一步省显存。
