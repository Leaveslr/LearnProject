# 验证案例：归并排序

## 目标

验证框架是否能讲清楚递归和分治类算法。

## 讲解大纲

### 问题场景

要把一堆数字排序。朴素地反复找最小值可以做，但当数据很多时，每次找都会重复扫描。

### 已有经验

整理两摞已经排好序的试卷：每次只比较两摞最上面的一张，把更小的拿出来。

类比边界：这个合并动作成立的前提是两摞内部已经有序。

### 直觉模型

归并排序把“大排序”拆成很多“小排序”：先把数组不断切半，直到每份只有一个元素；单个元素天然有序；再把有序小段合并成更大的有序段。

### 手算

数组：`[8, 3, 5, 2]`

1. 拆成 `[8, 3]` 和 `[5, 2]`。
2. 再拆成 `[8] [3] [5] [2]`。
3. 合并 `[8]` 和 `[3]` 得到 `[3, 8]`。
4. 合并 `[5]` 和 `[2]` 得到 `[2, 5]`。
5. 合并 `[3, 8]` 和 `[2, 5]` 得到 `[2, 3, 5, 8]`。

### 最小形式化

- 分解：把数组分成左右两半。
- 解决：递归排序左右两半。
- 合并：把两个有序数组合成一个有序数组。

### 易错点

- 学生容易以为“拆开”本身完成排序，实际上排序发生在合并阶段。
- 合并时忘记处理某一边剩余元素。
- 递归停止条件不清楚。
- 空间复杂度容易被忽略。

### 复杂度

每一层合并都要处理所有 `n` 个元素。切半会产生 `log n` 层，所以总时间是 `O(n log n)`。

## 验证结论

该框架适合归并排序，但需要额外强调递归的“信任契约”：假设左右两半已经被排好，当前层只负责合并。
